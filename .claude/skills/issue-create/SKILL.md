# 이슈 생성 절차

1. 근거 문서(docs/ 아래)를 읽는다. 근거 문서가 없으면 만들지 말고 어떤 문서를 기준으로 할지 묻는다.
   - 라맵: 스펙은 `docs/planning/` 01~19, 구현 계획·조사는 `docs/plans/`. 할지 말지 정할 후보는 `docs/planning/19.백로그.md`에만 있다 — 백로그 항목을 이슈로 만들 때는 그 행과 연결된 문서를 근거로 쓴다
2. 분할안을 목록으로만 보여 준다. GitHub에는 아직 올리지 않는다.
   - 이슈마다: 제목, 목표 한 줄, 근거 문서의 절, 충돌 주의(같은 파일을 건드리는 다른 이슈)
   - 이슈 하나는 PR 하나로 끝낼 크기로 나눈다.
3. 사용자가 승인한 항목만 GitHub MCP `issue_write`(method: create)로 만든다. 승인 없이 만들지 않는다.
4. 본문은 아래 양식을 그대로 쓴다. 근거 문서에 없는 기능이나 범위는 넣지 않는다.
5. 백로그 항목으로 만든 이슈면 `19.백로그.md` 그 행의 상태를 "채택"으로 바꾸고 비고에 `#이슈번호`를 적는다(후보 목록과 이슈가 따로 놀지 않게). 이 수정은 docs 1파일이라 main 직접 커밋 예외에 해당한다

## 본문 양식

```markdown
## 목표

(한두 줄)

## 범위 밖

(이번에 하지 않는 것)

## 완료 조건

- [ ] ...

## 근거 문서

docs/... (절 번호까지)

## 충돌 주의

(없으면 "없음")

## 작업 유형

(UI / 데이터 / 파이프라인 / 문서 중 해당하는 것. UI면 ramap-ui 스킬, 매장 데이터면 data-integrity·closure-verification 스킬을 따른다)
```
