# 데이터 신뢰도 — 다른 가게 정보가 번지지 않게 (라맵)

## 왜 필요한가

조사 결과(`data/enrichment/*.json`)는 상호 **접두 일치**로 매장에 붙는다. 체인 지점(코이라멘 → 코이라멘 장충점)에 정보를 나누려는 장치였는데, 2026-10-27 감사에서 이것이 대량 오염원으로 드러났다.

- 이름만 겹치는 다른 가게: "라멘야"(김포) → 라멘야누·라멘야서면롯데에 김포 인스타·장르
- 한 지점의 사실이 체인 전체로: "코이라멘 지로"의 지로계 → 코이라멘 21개 지점(지로계 42곳 중 절반이 오류)
- 짧은 이름 매장이 긴 이름의 다른 가게 정보로 **게재 자체가 된 경우**: 용산 "우마미"(회·오마카세)·부천 "키레이"(의류) 등 라멘집이 아닌 곳 8곳이 라멘집으로 게재돼 있었다

**원칙: 같은 가게·같은 체인이라는 근거가 있을 때만 정보를 나눈다. 모르면 비워 둔다.** 틀린 정보보다 빈 정보가 낫다(폐업 검증과 같은 원칙 — `.claude/skills/closure-verification`).

## 승계 규칙 (코드로 강제 — `scripts/lib/enrich.ts` `isSameChain`·`mergeMatched`)

| 정보                                  | 정확 일치(같은 이름)                | 접두 일치(이름이 더 길거나 짧음)                        |
| ------------------------------------- | ----------------------------------- | ------------------------------------------------------- |
| 장르(국물·형태)·세부                  | 붙음                                | **같은 체인으로 판정될 때만**                           |
| 인스타                                | 붙음                                | 같은 체인 + 항목에 `addrHint`가 있으면 그 주소 매장에만 |
| 계보(이에케·지로계·자가제면·본토직영) | 붙음                                | **`chainWide: true` 항목만**                            |
| 영업시간·메뉴 등 위치 필드            | 붙음(동명 다지점은 addrHint 일치만) | 안 붙음                                                 |

같은 체인 판정(`isSameChain`) — 짧은 이름 뒤에 남는 글자가:

- 번호, 또는 "…점/본점/호점/직영점"이면서 **단어 경계**(띄어쓰기·`_`·`(`)나 주소 지명으로 시작 → 같은 체인 ("코이라멘 장충점", "코이라멘수지구청역점")
- 매장 주소에 들어 있는 지명 → 같은 체인 ("오레노라멘송파")
- 그 외 → **다른 가게** ("라멘야누", "멘야하나비 합정점" ← "멘야하나")
- 괄호 별칭은 떼고 비교 ("쿄라멘(Kyo ramen)" = "쿄라멘")
- 브랜드에 `chainWide: true` 항목이 하나라도 있으면(체인 선언) 그 브랜드의 모든 항목이 띄어쓰기 없는 "…점"에도 넘어간다. 선언 근거 = 공공데이터에 같은 상호 "…점" 지점이 여럿이거나 공식 소개. 범용 상호(미스터라멘·우마이라멘처럼 무관한 가게가 같은 이름을 쓰는 경우)는 선언하지 않는다

## 항목을 추가·수정할 때

1. **특정 매장을 조사한 항목에는 `addrHint`(도로명+번호)를 반드시 넣는다** — 그 매장의 인스타·위치 필드가 다른 지점으로 번지지 않는다
2. **계보는 지점별 근거가 있을 때만 그 매장 이름으로 넣는다.** 체인 전 지점이 같은 계보라는 근거(공식 소개·브랜드 정의)가 있을 때만 `chainWide: true`. 미디어 기사 한 줄로 체인 전체를 단정하지 않는다
3. 이름만 겹치는 별개 가게는 그 매장 항목에 `standalone: true` — 양방향 승계 차단
4. 라멘집이 아니면 `soupDetail: ["라멘집 아님"]`, 실존 근거가 없으면 `["실존 미확인"]` (게재 게이트가 제외·보류)
5. 근거는 `sourceNote`에 출처 종류·날짜와 함께 (Daum 장소 카드·블로그 후기 날짜). 디렉터리 재게시는 근거가 아니다

## 재생성 후 검수 (필수)

```
npm run enrich-candidates -- data/out/candidates.tsv data/enrichment/*.json
npm run sync-sheet -- data/out/seed.tsv
npm run audit-integrity            # 기준: git HEAD의 data/shops.json
```

`data/out/integrity-report.md`를 읽고:

| 리포트 구역                      | 반영 전에 할 일                                                                                                                                                                                                             |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 소실(게재 → 비게재)              | **한 곳도 빠짐없이 사유 확인.** 실재 라멘집이면 `npm run collect-evidence`로 근거를 모아 그 매장 이름의 항목을 추가해 살린다. 라멘집이 아니면 `라멘집 아님`. Supabase `records`에 그 shop_id 기록이 있으면 PO에게 먼저 보고 |
| 계보 변경                        | 필터·`/style/*` 페이지에 바로 반영되므로 매장별 근거 확인. 체인 전체 사실이면 `chainWide`, 아니면 제거 유지                                                                                                                 |
| 장르·인스타 변경                 | 표본을 열어 "다른 가게 정보가 빠진 것"인지 "같은 가게 정보가 끊긴 것"인지 판정. 후자는 항목 보강                                                                                                                            |
| 주소가 다른 매장끼리 같은 인스타 | 체인 공식 계정이 아니면 오염 의심 — 지점 계정이면 `addrHint` 추가                                                                                                                                                           |

**반영 금지 조건:** 소실·계보 변경 중 사유를 확인하지 못한 행이 하나라도 있으면 반영하지 않는다(PR에 "검수 미완"으로 남긴다).

## 보고

PR·답변에 `audit-integrity` 첫 줄(변경·계보·소실·신규·인스타 공유 수)과, 소실 매장 표(판정·근거), 계보 변경 표를 붙인다.
