# 라멘집 사진은 완식과 별도인 사용자 기여 트랙으로 받는다

## 맥락

1,245곳 중 매장 사진이 있는 곳이 없다. 사진을 올리는 길은 완식 사진(로그인 + 완식 필수) 하나뿐이고, 승인된 사진은 1장이다. PO의 우선 목적은 **주문 전에 메뉴판 확인**이다. 시중 사진은 저작권과 [타사 데이터 경계](0002-third-party-data-boundary.md) 때문에 쓸 수 없다. 조사: [사진 확보 조사](../research/2026-11-02-photo-contribution.md).

## 결정

**공급 순서**
1. 바탕: PO가 인기 라멘집 메뉴판을 직접 찍고, 인스타그램 메시지로 허락받은 사장님 사진을 올린다. 라멘갤에는 부매니저 허락을 받아 소개글을 쓴다.
2. 등록 장치: 아래 사진 기여 트랙.
3. 보상: 사용자가 늘어난 뒤 기간 한정 기프티콘(메뉴판이 없는 곳의 첫 승인만, 월 상한). 휴대전화번호를 받기 전에 개인정보처리방침을 개정한다.

**사진 기여 트랙**
- 완식 사진(내 기록)과 별개로, 누구나(비로그인 포함) 라멘집 사진을 올린다. 종류는 라멘·메뉴판·외관·내부.
- 입구: 상세 사진 자리(없으면 [첫 사진 올리기], 있으면 앨범의 [사진 올리기]), 대표 메뉴 아래 [메뉴판 올리기], 완식 저장 직후 한 번 제안. 상세에는 이미 채운 버튼 [완식]이 있으므로 사진 입구는 모두 보조 버튼이다.
- 올리기 시트: 종류 칩(입구에 따라 미리 선택) → 사진 최대 5장 → "직접 찍은 사진이고, 라맵에 공개해도 좋아요" 체크 → [N장 올리기]. 촬영 월은 위치정보를 지우기 전에 사진 날짜만 읽어 남긴다.
- 표시: 라멘 → 외관 → 내부 순으로 상세 갤러리(첫 장은 og:image), 메뉴판은 대표 메뉴 아래 최신순 + `YYYY.M 촬영`. 로그인한 기여자는 닉네임을 붙이고 비로그인은 날짜만.
- 검수: `/admin` "라멘집 사진" 탭에서 묶음 단위로 사진별 종류 수정·승인·반려, 공개된 사진 내리기. 반려 사유 칩: 다른 가게·본인 촬영 아님·알아보기 어려움·사람이 보임·중복·부적절·삭제 요청.

**저장과 공개**
- `shop_photos` 테이블(대기·승인·반려)과 **공개 버킷** `shop-photos`. 서버 렌더·og:image·구조화 데이터에 만료 없는 주소가 필요해서 서명 URL을 쓰지 않는다. 파일 이름은 UUID, 반려된 파일은 지운다.
- 매장 페이지는 서버에서 승인 사진을 읽는다. 승인·내리기 때 관리자 확인을 거친 서버 함수가 그 매장 경로만 `revalidatePath`로 무효화한다([ISR 결정](../modules/platform/decisions/0003-runtime-page-generation.md)의 "배포 때만 바뀜"에 대한 예외).
- 남용 방지: 기기당 하루 100장(화면), 라멘집당 대기 30장·전체 대기 500장(DB 트리거). IP는 기록하지 않는다.
- 탈퇴하면 그 사람의 사진도 지운다(완식 사진과 같다).

**약관**: 제7조가 "제보와 완식 기록(사진·한줄평)"만 적고 있어 라멘집 사진을 더한다. 시행일·공지는 PO가 정한다.

## 근거

- 사용자 기여만으로 처음부터 채운 서비스는 없었다(카카오맵·배민은 사장님 사진, Zomato는 창업자 직접 스캔, Yelp는 한정 유급 작성자).
- 로그인 필수 전환은 고품질 기여를 더 크게 줄였다(Hill & Shaw 2020). 품질은 사전 검수로 막는다.
- 방문 직후 요청(캐치테이블·Google·Apple), 5장 상한(배민), 사용자가 고르는 종류(네이버 제보), 빈 상태의 바로 올리기(NN/g).
- 승인 즉시 공개돼야 "올리면 내 닉네임으로 걸린다"는 동기가 산다.

## 영향

- 비로그인 사진도 들어오므로 검수 부담이 PO에게 생긴다. 대기 상한으로 대기열 크기를 묶는다.
- 공개 버킷이라 대기 중 사진도 주소를 아는 사람(올린 본인)은 열 수 있다.
- Supabase 무료 저장 1GB(장당 약 300KB면 약 3,000장 [추측]). 1,000장을 넘으면 업로드 크기를 줄인다.
- 출시는 이슈 4개: DB → 표시 → 검수 → 올리기. 운영 DB 적용은 PO 승인 후.

## 버린 안

- 시중 사진 사용, 인스타그램 공식 임베드(우리 갤러리·og:image에 못 씀), 구글 Places 사진
- 제보(`reports`)에 사진 종류 추가 — 공개가 다음 데이터 반영·배포까지 늦어진다
- 완식 사진 테이블 확장 — 로그인 필수 구조
- 클라이언트에서만 사진 읽기 — 검색 노출·og:image에 사진이 안 들어간다
- 다음 배포까지 공개 대기 — 기여 동기와 어긋난다
- 검수자가 종류를 붙이기 — 조사 결과 사용자 선택(기본값 미리 선택)이 표준
- 배지·등급·리더보드, 건당 현금 보상
