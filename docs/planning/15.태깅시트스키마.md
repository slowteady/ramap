# 15. 태깅 시트 스키마 — 파트너 작업용 (크리티컬 패스)

원칙: **이 시트 구조 = DB 스키마 = 어드민.** 컬럼을 여기서 확정하면 이후 마이그레이션 없이 시트→DB→어드민으로 이어진다. 구글시트 1개 문서에 시트(탭) 3개.

## 시트 1: 매장 (본체)

### A. 식별·위치 (시딩 시 자동 채움 — LOCALDATA)

| 컬럼 | 형식 | 규칙 |
|---|---|---|
| id | 텍스트 | 로마자 슬러그, URL에 사용 (예: `kinka`, `menya-konoha`). 유일값 |
| 상호 | 텍스트 | 간판 기준 (예: 킨카) |
| 지점명 | 텍스트 | 있을 때만 (예: 성수점) |
| 주소 | 텍스트 | 도로명 주소 |
| 시 / 구 | 드롭다운 | 행정구역 |
| 동네라벨 | 드롭다운 | SEO·표시용 상권명 — 상권 구획·명칭은 **캐치테이블 지역 필터를 따른다** (2026-08-28 실측: 강남/역삼/선릉 · 강남구청 · 건대/군자/구의 · 금호/옥수/신당 · 명동/을지로/충무로 · 방이 · 북촌/삼청 · 삼성/대치 · 상수/합정/망원 · 서울역/회현 · 서초/방배 · 서촌 · 성수/서울숲 · 신사/논현 · 신촌/홍대/서교 · 압구정 · 압구정로데오 · 청담 · 양재/도곡 · 연남 · 영등포/여의도 · 용산/삼각지 · 이태원/한남 · 잠실/송파 · 종로/광화문). 슬래시 번들 중 매장이 속한 **개별 상권명 하나**를 기입 (예: 성수/서울숲 번들 → `성수` 또는 `서울숲`) — 캐치테이블 목록 카드도 "청담 · 양식"처럼 단일 상권명 표기. 캐치테이블 목록에 없는 동은 가장 가까운 번들의 구성원 명으로 (예: 자양동 → `건대`). 행정동·법정동 이름 금지 |
| lat / lng | 숫자 | 좌표 |
| 좌표출처 | 드롭다운 | `LOCALDATA` / `수동핀` (지오코딩 API 저장 금지 — 09번 문서) |

### B. 영업 정보

| 컬럼 | 형식 | 규칙 |
|---|---|---|
| 영업시간 | 텍스트 | `11:30-21:00` 형식(복수 구간은 쉼표 `11:00-15:00,17:00-21:00`, 심야는 `18:00-02:00`). 이 형식이어야 실시간 영업중 표시가 작동, 아니면 시간 텍스트만 노출 |
| 브레이크 | 텍스트 | 예: `15:00–17:00`, 없으면 공란 |
| 휴무 | 텍스트 | 예: `월`, `둘째 화` |
| 오픈일 | 날짜 | 인허가일 기준, 확인되면 실제 오픈일로 교체. 신규 오픈 섹션의 원료 |
| 상태 | 드롭다운 | `영업` / `휴업` / `폐업` — **폐업은 행 삭제가 아니라 상태 변경** (기록 보존) |
| 상태변경일 | 날짜 | 상태가 바뀐 날 |

### C. 택소노미 (파트너의 본 작업 — v2.1 기준)

| 컬럼 | 형식 | 값 |
|---|---|---|
| 형태 | 복수 (콤마) | `라멘, 츠케멘, 마제소바, 기타` |
| 형태_대표 | 드롭다운 | 위 중 1개 필수 — 필터·정렬·SEO 기준값 |
| 스프 | 복수 (콤마) | `돈코츠, 쇼유, 시오, 미소, 돈코츠쇼유, 니보시, 토리파이탄, 탄탄멘, 기타` |
| 스프_대표 | 드롭다운 | 위 중 1개 필수 |
| 스프_세부 | 복수 (콤마) | 내부 보관용 세분값: `교카이, 니보시청탕, 니보시파이탄, 시오돈코츠, 카레` 등 — UI 미노출, 5곳 넘는 값은 분리 승격 (10번 문서 원칙) |
| 계보 | 복수 (콤마) | `이에케, 지로계, 자가제면, 본토직영` |
| 편의 | 복수 (콤마) | `식권기, 카에다마, 원격웨이팅, 한정메뉴, 심야, 주차, 1인카운터` |
| 태깅확신도 | 드롭다운 | `확정`(방문 또는 확실) / `추정`(메뉴판·인스타로 원격 판별) — 추정은 출시 후 제보로 검증 |

### D. 콘텐츠

| 컬럼 | 형식 | 규칙 |
|---|---|---|
| 대표메뉴1~3 | 텍스트 | `메뉴명|가격` (예: `니보시 시오 라멘|12000`). 1은 필수 — 장르 판별 근거이자 가격대·SEO 원료. 전체 메뉴판은 수집 안 함 (기확정) |
| 사진 | 텍스트 | Storage 공개 버킷 경로, 콤마로 복수. 첫 장이 대표 (2026-09-01 추가) |
| 좌석 | 텍스트 | 예: `카운터 9, 테이블 2` |
| 한줄소개 | 텍스트 | 선택. 40자 이내, 에디토리얼 톤 |
| 인스타 | URL | 매장 계정 |
| 네이버플레이스 | URL | 전체 메뉴·리뷰 위임 링크 |
| 웨이팅링크 | URL | 캐치테이블/테이블링 (있을 때) |

### E. 검증·운영

| 컬럼 | 형식 | 규칙 |
|---|---|---|
| 검증상태 | 드롭다운 | `운영자확인` / `제보검토중` — 운영자확인은 **사람이 실제 검수(제보 처리·현장 확인)했을 때만** 올린다. 조사 기반 자동 신뢰도는 태깅확신도가 담당하고 UI "확인됨" 칩으로 노출(2026-09-04 PO 확정 — 자동 산정 축 이원화 논의 끝에 태깅확신도로 통일) |
| 최종확인일 | 날짜 | 정보를 마지막으로 검증한 날 — 오래되면 재확인 대상 |
| 정보출처 | 텍스트 | 예: `방문`, `인스타`, `제보#12` |
| 메모 | 텍스트 | 자유 |

## 시트 2: 소목록 (큐레이션 — 참여 1단·SEO 연동)

"서울 이에케 4/7" 진행률과 `/seoul/iekei` 류 페이지의 원천. **10곳 내외 유한 목록** 원칙 (14번 문서).

| 컬럼 | 형식 | 규칙 |
|---|---|---|
| 목록id | 텍스트 | 슬러그 (예: `seoul-iekei`) |
| 목록명 | 텍스트 | 예: `서울 이에케` |
| 기준 | 텍스트 | 지역×장르/계보 조합 설명 |
| 매장ids | 복수 (콤마) | 시트1의 id 참조, **7~12개 권장** |
| 노출 | 드롭다운 | `공개` / `준비중` — 매장 3곳 미만 조합은 공개 금지 (SEO 씬 페이지 방지, 13번 문서) |

## 시트 3: 제보 (폼 자동 적재 — 검수 대기열)

| 컬럼 | 출처 |
|---|---|
| 접수일시, 유형(신규/수정/폐업), 가게명, 링크/위치, 내용 | 폼 자동 |
| 처리상태 (`대기`/`승인`/`반려`/`보류`), 처리일, 처리메모 | 파트너 입력 |

- 승인 시: 시트1에 반영하고 처리메모에 매장 id 기록
- **폐업 제보는 2차 확인(전화·인스타) 전 승인 금지** (기확정 규칙)

## 운영 규칙

1. **작업 순서:** 아는 집(확신도 `확정`)부터 → 유명한데 안 가본 집(인스타로 `추정` 태깅) → 시딩 목록의 나머지. 아는 집 100곳이 추정 300곳보다 가치 있음
2. **물량 목표:** 수도권 300곳 (매장당 확정 3~5분 / 추정 ~10분, 주 5시간 기준 6~10주)
3. **드롭다운 강제:** C열 전부 데이터 검증(드롭다운)으로 잠가 오타 방지 — 자유 텍스트로 태깅하면 나중에 전부 재작업
4. **경계 사례 발견 시 즉시 기록:** 분류가 안 되거나 두 값에 걸치는 집은 메모에 남김 — 택소노미 v2.1 검증(시험 분류)의 실데이터가 됨
5. 시트 헤더 행은 이 문서와 1:1 유지 — 컬럼 추가·변경은 반드시 이 문서 갱신과 함께
