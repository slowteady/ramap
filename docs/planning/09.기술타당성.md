## 모듈화 원칙 (2026-08-26 확정) — "로그인은 맨 마지막" 전제

로그인은 v1 제외, 트리거(동기화 문의 발생 또는 집단 참여 개방) 시 **카카오 소셜 로그인**을 Supabase Auth로 즉시 도입. 이를 위한 이음새 4개를 처음부터 분리:

1. **기록 저장소 추상화** — UI는 RecordStore 인터페이스만 호출. v1=localStorage 구현체, 도입 시=Supabase 구현체 교체 + 기존 기록 이관 필수
2. **사용자 식별 추상화** — "현재 사용자" 개념을 익명(null)으로 시작, 로그인 도입 시 카카오 세션으로 채움
3. **제보 제출 계층 분리** — 제보는 로그인 도입 후에도 계속 무로그인
4. **지도 어댑터** (기존 확정)

**기록 스키마가 계약:** JSON 내보내기 포맷 = localStorage 저장 형태 = 향후 Supabase 테이블 형태로 동일 유지 → 이관이 변환 없는 업로드가 됨. 로그인 도입 시 개인정보처리방침·최소 수집(카카오 식별자만) 숙제 발생함을 기록해둠.

## 핵심 발견: 지오코딩 결과 저장은 3사 모두 약관 금지

- 네이버: Maps 약관 제7조 ⑪ "결과 데이터의 저장·DB화·재사용 엄격 금지" (명문)
- 카카오: 데브톡 운영진 답변 3건 — "실시간 호출만 허용, 제휴·유료로도 저장 검토 안 함"
- VWorld: "실시간 사용, 별도 저장 불가" 명시

→ **"주소 일괄 지오코딩 후 자체 DB 저장" 아키텍처는 금지.** 좌표는 공공데이터에서 확보(저장 제약 없음). 자체 확보 좌표를 카카오 지도에 마커 표시하는 구조는 카카오 운영진이 명시 허용 답변(장소ID·place_url 저장도 허용). 운영자가 직접 확정한 수동 핀도 저장 허용.

## SEO 설계 원칙

- 지역×장르 페이지는 지도 없이 완결된 HTML로 SSR (리스트·주소·구조화 데이터)
- 지도는 뷰포트 진입 시 lazy-load — 크롤러가 쿼터 소모 안 함
- 정적 지도 이미지 사전 생성·캐싱 금지 (약관 위반)
