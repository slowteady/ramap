# 08. MVP 기능 정의

## MVP가 검증할 핵심 가설

> "라오타는 장르 필터가 있는 검증된 라멘 DB에 반응한다 (방문하고, 커뮤니티에 공유하고, 제보한다)"

이 가설 검증에 필요 없는 기능은 전부 제외.

## MUST

| 기능 | 이유 |
|---|---|
| **라멘 DB 300곳+ (수도권 우선), 장르·속성 태깅 완료 상태로 출시** | 제품의 본체. 유저 0명일 때 제보 폼은 빈 상자 — 콜드스타트는 팀이 채운 데이터로 돌파 |
| **지도 뷰 + 장르 필터** | 카카오 JS SDK, 마커·클러스터링. "지도에서 이에케이만 보기"가 핵심 경험 |
| **매장 상세 페이지 (SSR)** | 장르·속성·기본정보 + 구조화 데이터 마크업 — SEO 단위 |
| **지역×장르 페이지 자동 생성** | "성수 츠케멘" 류 롱테일 — 트래픽 엔진. 지도는 lazy-load |
| **제보·수정 폼** | 로그인 없이 제출 → 운영자 승인. 유저 검증 구조(3층 루프)의 최소형 |
| **먹었다·저장 기록 (참여 1단)** | 좋아요식 토글 — 가게당 1회, 재클릭은 해제(카운트 누적 없음, 어뷰징 차단. 2026-08-28 결정, 구 명칭 완식·가고싶다). 서버 저장 환경에선 로그인 필수(비로그인 클릭 시 카카오 로그인 유도), 날짜 저장, 방문 매장 회색조 마커, 온보딩 "가본 집 먼저 찍기", 장르×지역 소목록 진행률, JSON 내보내기/복원. 근거·금지사항은 14.참여리텐션설계 |

### 택소노미 (→ 10.택소노미초안.md의 v2로 대체됨)

- v1의 평면 리스트는 폐기. ramendb 실구조 분석 결과 **3축 구조**(제공 형태 × 스프 계열 × 계보·특성 태그)로 재설계 — 경계 사례(츠케멘×돈코츠교카이, 이에케이=돈코츠쇼유+계보태그)가 구조적으로 해소됨
- 파트너 검수 포인트 5건은 10번 문서 참조

## SHOULD (첫 반응 후 빠르게)

- **신규 오픈 섹션** — 재방문 훅 1순위, MVP 직후 최우선
- **공유 이미지 (참여 2단)** — 단일 짤(완식 총수+내 지도+최다 장르+인생 라멘 3~4곳), 소목록 완주 인정증, 연말 "Year in 라멘". 상세는 14번 문서
- **장르 가이드 페이지** ("이에케란?") — 라이트층 교육 + SEO 보조

> 저장 기능은 '완식·가고싶다 기록'으로 스펙 확정되어 MUST로 승격 (2026-08-26, 리텐션 리서치 근거)

## LATER (명시적으로 안 만듦)

- 로그인·계정 (필요해지는 날이 성공한 날)
- 리뷰·평점 (3막 — 콜드스타트 함정)
- 어워드 (3막), 면 확장 버티컬 (2막 — 단 스키마는 다중 버티컬로 선설계)
- 앱, 예약, 수익화

## 빌드 순서

1. 택소노미 확정 (파트너)
2. DB 스키마 설계 — 다중 버티컬 구조 (빌더)
3. 데이터 파이프라인: LOCALDATA 시딩 → 태깅 툴 → 파트너 태깅 시작
4. 웹 프론트 (태깅과 병렬 진행 — 2인 효율 최대화)
