# 13. UI 설계 원칙 — BP 딥다이브 + 심미 레퍼런스 종합

조사일: 2026-08-26. 근거: 멀티에이전트 딥다이브 2건 (BP 6에이전트: 해외/국내/필터 문헌/모바일 지도/SEO 하이브리드 + 심미 레퍼런스 2에이전트: 국내 8개·해외 7개 실서비스 관찰). 방침: **구조·동작은 한국 컨벤션 차용, 시각 언어는 미려 레퍼런스 기준.**

## A. 디자인 토큰 규율 (깔끔함의 8할)

국내 상위 서비스(토스·오늘의집·29CM·당근·무신사·캐치테이블·컬리) 실측에서 공통 공식 확인:

- **색 예산:** 흰 배경 + 그레이 3~4단 + **유채색 정확히 1색**(액센트). 상태 표현은 새 색이 아니라 반전·보더·명도 차로만. "색이 있는 곳 = 누를 수 있는 곳" 규칙(컬리)
- **radius 3~4종 고정.** 형태 문법 분리: 콘텐츠(사진 카드) 4~12px 각지게, 컨트롤(칩) 완전 pill (무신사·캐치테이블)
- **폰트:** Pretendard(업계 표준), 스케일 5~6단 고정, **위계는 크기보다 굵기(400/600/700)와 그레이 단계로** (당근 SEED)
- 카드 구획은 그림자·테두리 대신 여백으로 (29CM)
- 텍스트 근흑(#1A1B1F류) 사용, 순흑 금지 (무신사)
- **토큰 외 값 사용 금지가 원칙 그 자체** (토스 TDS)

시각 벤치마크 배정: 앱 구조·검색·카드 = **캐치테이블**(도메인 최근접) / 지도 화면 = **호갱노노** / 바텀 카드·상세 탭 = **오늘의집** / 토큰 규율 = **토스**.

## A-2. 플랫폼·라벨 확정 (2026-08-26)

- **모바일웹 퍼스트.** 근거: ① 사용 맥락(이동 중 탐색) ② 구글 모바일 퍼스트 인덱싱 — SEO 엔진 전략상 랭킹 판정 자체가 모바일 버전 ③ 벤치마크 전부 모바일 우선. 데스크톱은 MVP에서 무붕괴 수준(콘텐츠 페이지 중앙 단일 컬럼), 스플릿 뷰는 트래픽 비중 확인 후. 앱 없음(기확정)
- **유저 기여 라벨: 헤더 버튼 = "제보하기"** (라멘투데이·포카맵 실측 — 갤러리 덕후에게 학습된 관례어, 커뮤니티 공략 멘트와 일관) / **매장 상세의 수정 진입점 = "정보 수정 제안"** (카카오·네이버 관례). 라이트층 확대 시 라벨 테스트는 미결 항목

## B. 홈(지도) 구조

- **모바일: 풀맵 + 논모달 바텀시트.** 지도는 뷰포트 높이 거의 전부. 스크롤 페이지 중간의 임베디드 지도는 제스처 충돌(scroll trap)로 금지 문헌 명시 — 카카오맵은 cooperative 제스처 옵션이 없어 더 치명적. SSR 관문 섹션은 스크롤 경계 아래로 분리, 하단에 스크롤 어포던스만
- **마커 탭 → peek 카드 → half → 상세 페이지 라우팅.** full 확장 대신 `/shop/{slug}` 이동(SEO상 고유 URL 필수). peek/half에서 지도 조작 가능, 그랩 핸들 + X 버튼 병행, 뒤로가기로 시트 닫힘(history 연동)
- **카드 좌우 스와이프 = 인접 매장 순회 + 핀 연동 하이라이트** (Yelp가 효과 공식 보고 — 지도 맥락 유지한 비교 탐색)
- **지도 이동 갱신:** 명시적 "이 지역 재검색" 버튼 (네이버·카카오·캐치테이블 한국 컨벤션) + 검색 기준 지역명 상단 표기
- **상태의 URL화:** 필터·시트 높이·선택 매장을 URL 쿼리로 (캐치테이블 실증) — 뒤로가기·공유·SEO 동시 해결. 갤러리에 "니보시만 켠 지도" 링크 공유가 곧 유통
- **위치 권한:** 진입 시 절대 요청 금지. 기본 서울 뷰 → '현위치' 버튼 탭에서만 요청 (맥락적 타이밍이 수락률 대폭 개선)
- 데스크톱 스플릿 뷰(좌 리스트+우 지도)는 표준이나 **투자 후순위** (모바일 트래픽 비중 확인 후)

## C. 마커·클러스터·카드

- **마커 = 미니 데이터 카드.** 핀이 아니라 1차 결정 변수를 직접 노출 (Airbnb 가격 핀, 호갱노노 "41평 35억" 라벨). 라맵의 결정 변수 = **스프 계열** → 색 인코딩(+필요시 약자), 범례는 필터 칩과 색 공유. 터치 타깃 44px, 색 외에 형태·크기 병행(접근성)
- **2단 위계:** 신규 오픈 NEW 배지 강조 핀 / 일반 핀. "N명 보는중" 류 소셜프루프는 초기엔 빈약함만 노출되므로 금지
- **마커 상태:** 선택(확대·반전) > 저장(북마크) > 기본 > **방문함(회색조)** — Airbnb viewed-grey, 재탐색 비용 절감 리텐션 장치. localStorage로 시작
- **클러스터: 숫자 원형이 아니라 행정구역 시맨틱 클러스터** ("성수동 12" 알약형) — 호갱노노·다방·캐치테이블 3사 공통 컨벤션, 동 단위 SEO 랜딩과 1:1 대응. 필터 적용 시 클러스터 숫자도 갱신(필터 작동 피드백). 밀집 상권 최대 줌 겹침은 spiderfy 대신 카드 스와이프로
- **카드 정보 순서: 실행 가능성 우선** — 영업중/휴무가 최상단, 그다음 매장명 → 장르 태그 → 거리 (캐치테이블 교훈). 메타는 중점 구분 1줄 스탯-로우("이에케 · 도보 5분 · 영업중")
- **저장 액션은 이진화:** 별점 위젯 대신 "가고 싶다 / 갔다(완식)" 2버튼 (Retty) — 리뷰 LATER 결정과 정합

## D. 필터 UX — 6칩 혼합안 기각

**확정 구조: 축 단위 칩 3개(형태/스프/계보) + 전체 필터 버튼.**
칩 탭 → 해당 축 값 선택 바텀시트(트레이 패턴: 결과 반투명 노출 + 결과 수 상시 표시). 선택 값은 칩 라벨에 반영("스프 · 돈코츠", 체크마크+채움), 개별 X + 전체 초기화.

- **기존 검토안("스프 칩들 + 츠케멘·이에케 승격 6칩") 기각.** 근거: ① 축 혼합은 NN/g 예측가능성 원칙 위반 — 특히 이에케(계보)는 스프가 사실상 돈코츠쇼유라 "돈코츠 칩과 이에케 칩이 배타인가 포함인가"의 선택 시맨틱이 정의 불가 ② Material ChipGroup 모델 위반(한 그룹 = 한 도메인) ③ 승격은 사용 데이터가 있을 때만 정당(Baymard) — 출시 전엔 근거 없음. **재도입 조건:** 출시 후 필터 로그에서 특정 값 사용이 압도적이면 "축 칩 3 + 인기 값 칩 1~2" 형태로, 전체 필터에 중복 유지하며 추가
- **적용 방식: 즉시 반영(interactive).** 탐색형 서비스 + 가벼운 데이터셋 — Apply 버튼 근거 없음. 값 옆에 현재 지도 범위 결과 수 표시, 0건 값 비활성(사전 예방). 0건 발생 시 배너 + 필터 칩 유지 + 완화 경로
- **계보 축:** 값 시트에 한 줄 설명 툴팁 필수(전문용어). 데이터 희소 시 필터가 아니라 **지도 레이어/렌즈**(호갱노노 테마 방식)로 전환 검토
- 필터 적용 시 지도 뷰포트 자동 이동 금지

## E. SEO 하이브리드 구조 (5개 서비스 전부 수렴한 결론)

**"지도 SPA는 SEO를 못 한다. 트래픽 엔진은 별도의 SSR 리스트 페이지망이다."** (Zillow·Yelp·Tripadvisor·Tabelog·Airbnb 공통 — Tabelog는 라멘 도메인 직접 선례)

- 홈 지도 = 인터랙션용 클라이언트 화면. **지역×택소노미 SSR 리스트 페이지망이 1급 시민** (`/seoul/mapo/tonkotsu/` 정적 경로)
- **조합 폭발 관리:** 매장 3곳+ & 검색 수요 있는 조합만 정식 URL·색인 허용, 나머지는 지도 쿼리 상태 + canonical 상위 정규화
- 리스트 템플릿: H1 연도 신선도("마포 돈코츠 라멘 맛집 N곳 (2026)") + SSR 카드 리스트 + 인근 지역·관련 장르 교차 링크 + **FAQ 섹션(택소노미 용어 해설 = 차별 자산이자 FAQPage 마크업 소재)**
- 구조화 데이터: 리스트 = ItemList(summary) + BreadcrumbList + FAQPage / 상세 = Restaurant(geo, openingHours, servesCuisine, priceRange)
- SSR 페이지의 지도는 facade(정적 프리뷰) + click-to-load — loading=lazy만으론 불충분, CLS 방지 컨테이너 크기 명시

## E-2. "AI티" 방지 게이트 (2026-08-26 — 빌드 시 매 화면 통과 필수)

원인 정의: AI티 = 레퍼런스 없이 기본값으로 생성된 흔적. 방어 = 실측 기반 토큰(A절) + 아래 금지 시그니처.

**금지 시그니처 체크리스트:**
- [ ] Inter/Roboto 등 기본 폰트 흔적 없음 (Pretendard만)
- [ ] 그라데이션 배경 없음 (사진 플레이스홀더 제외)
- [ ] rounded-2xl 남발 없음 — radius는 카드 8~12 / 칩·버튼 pill / 그 외 금지
- [ ] 이모지 아이콘 없음 (lucide 라인 아이콘만)
- [ ] 유리 효과(backdrop-blur 카드) 없음
- [ ] 테두리+그림자 이중 카드 없음 — 여백 구획 우선 (29CM)
- [ ] shadcn 기본 팔레트 잔재 없음 (slate/zinc 기본값 → 우리 그레이 토큰)
- [ ] 보라-파랑 계열 액센트 없음 (라멘 레드 1색)
- [ ] 화면을 무드보드 스크린샷 옆에 놓고 비교했는가 (무드보드: 두 분이 Mobbin·실서비스에서 10~15장 수집 — 빌드 전 준비물)
- [ ] 최종 질문: "이 화면이 어느 서비스 것인지 가릴 수 있는가" — 가려지면 실패 (무국적 = 슬롭)

**금지 패턴 (구조 차원 — AI 단골 레이아웃):**
- [ ] 아이콘+제목+설명 3열 특징 카드 그리드 없음 → 에디토리얼 문장 속 인라인 정보로 (Culture Trip·Hitosara)
- [ ] 중앙 정렬 히어로(제목+서브+CTA 2개) 없음
- [ ] 숫자 나란한 통계 밴드 없음 (다크 헤더의 인라인 통계는 실측 출처 있어 예외)
- [ ] 섹션 제목 위 pill 배지("✨ NEW" 류) 없음
- [ ] 아이콘 원형 파스텔 배경 없음
- [ ] 모든 섹션이 동일 리듬(제목-설명-그리드) 반복 없음
- [ ] 페이지 끝 CTA 밴드 재등장 없음
- [ ] 3단계 스텝퍼 온보딩 없음 (우리 온보딩은 단일 화면 체크 그리드 — 유지)
- [ ] **대원칙: 모든 레이아웃 패턴은 실측 레퍼런스 출처를 댈 수 있어야 함. 출처를 못 대면 반사신경 = 제거 대상**

**목업 감사 결과 (2026-08-26):** 장르 가이드의 "특징 3칸 그리드"는 이 게이트 위반 — 빌드 시 에디토리얼 인라인으로 교체. 계보 랜딩의 레터스페이싱 배지는 경계선 — 다크 헤더 안이라 유지하되 재검토. SEO 리스트 FAQ는 실측 출처(Yelp·Tripadvisor) 있어 통과, 단 기본 아코디언 스타일 금지.

**소급 적용 완료 (2026-08-26 목업 v3):** 장르 가이드 = 3칸 그리드 제거, 에디토리얼 프로즈+인라인 강조로 전면 개편 (Culture Trip·Hitosara). 계보 랜딩 = 레터스페이싱 배지 제거, 한자 병기 헤드라인으로. SEO 리스트 FAQ = 아코디언 박스 제거, 답변 노출형 Q&A (콘텐츠가 HTML에 노출돼 SEO에도 유리).

적용 시점: shadcn 테마 토큰 정의(빌드 1주차)가 이 게이트의 기술적 실행 — 토큰으로 덮기 전 기본값 사용 금지.

# 라맵 UI 규율

- radius: 카드 8~12px / 칩·버튼 pill(9999px) / 그 외 금지
- 폰트: Pretendard, 스케일 5~6단 고정, 위계는 크기보다 굵기(400/600/700)
- 카드 구획은 그림자·테두리 대신 여백. 아이콘은 lucide 단일 세트
