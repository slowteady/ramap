# 16. 제보·운영 플로우

원칙: **입구는 최대 개방, 출구는 전건 검수** (라멘 투데이 검증 공식). 검수·반영의 주 담당은 파트너(라오타), 빌더는 파이프라인만 — 판정→반영 사이에 개발자 손이 끼면 안 됨.

## 제보 폼 (입구)

- 로그인 없음, 익명 허용
- **2026-08-31 재설계:** 유형 선택 없음 — 진입점이 유형 결정 (17번 §8). **새 라멘집 등록** 폼은 **링크 우선**: 필수 = 가게 이름 + 링크(인스타·카카오맵·네이버, 최대 3) 또는 지도 위치 핀 / 선택 = 국물·종류·스타일 칩(라오타만 아는 정보), 사진, 한마디. 영업시간·메뉴·주소·좌석·편의는 **묻지 않는다** — 링크에서 파트너가 확인(라멘투데이 "가게명/링크만" 모델, 사용자 재타이핑 제거). 검수 = 링크 열어 시트 컬럼 채우기
- 사진: 직접 촬영 동의 체크(사진 첨부 시 필수, 09 경계선) → 클라이언트 리사이즈 1600px·JPEG 재인코딩(EXIF 제거) → Supabase Storage `report-photos` 비공개 버킷(익명 업로드만, 열람 불가) → 검수 승인분만 공개 이동
- 제출처: v1은 Supabase 테이블 (자체 폼 — 외부 폼 임베드보다 UX 우위, 09번 스택 결정에 따라)
- 스팸 방어: IP 속도 제한 + 허니팟 필드. 기기 핑거프린팅 금지 (기확정)
- 검수 안내는 폼 안이 아니라 **완료 화면**에만 (카카오·네이버·포카맵 관례, 버튼 아래 캡션 금지): "등록 요청을 받았어요 / 확인 후 지도에 올려드려요. 보통 며칠 안에 반영돼요."

## 검수 플로우 (출구)

```
제보 접수 → [제보 시트/테이블] 자동 적재 (상태: 대기)
    ↓ 파트너 검수 — 주 2~3회 확인 권장
    ├─ 승인 → 매장 시트에 반영 (신규: 태깅 포함 / 수정: 해당 필드 갱신 + 최종확인일 기록)
    ├─ 반려 → 처리메모에 사유
    └─ 보류 → 추가 확인 필요 건
    ↓ (자동) 동기화 → 사이트 반영
```

### 유형별 규칙

| 유형 | 규칙 |
|---|---|
| 새 라멘집 | 실존 확인(인스타·전화) → 시딩과 동일한 태깅 절차. 확신도 `추정`으로 시작 가능 |
| 정보 수정 | 교차 확인 후 반영. 장르 이견은 라오타가 최종 판정 — 제보는 입력이지 판결이 아님 |
| **폐업·휴업** | **2차 확인(전화·인스타·인허가 diff) 전 반영 금지.** 오폐업 표시는 매장에 실해를 끼치는 유일한 케이스 — 최고 엄격 |

## 자동 감지 루프 (제보와 병행)

- **신규 오픈:** LOCALDATA 월 1~2회 diff → 키워드 매칭 신규 인허가 = 후보 자동 추출 → 파트너 확인·태깅 → 신규 오픈 섹션 게재
- **폐업:** 같은 diff에서 영업상태 변경 감지 → 상태 `폐업` 전환 (이건 행정 데이터라 2차 확인 불요)

## 운영 리듬 (파트너 기준)

- 제보 검수: 주 2~3회, 회당 ~15분 (초기 예상량 일 0~5건)
- 인허가 diff 확인: 월 1~2회
- 검증 노후 관리: `최종확인일` 오래된 매장 순으로 틈틈이 재확인 — 완벽 추적이 아니라 "라멘GPS·자작 지도보다 덜 낡은 상태" 유지가 목표

## 확장 트리거

- 제보가 주간 수십 건을 넘어 시트 검수가 버거워지면 → 자체 어드민 웹 (시트와 동일 스키마라 마이그레이션 없음)
- 특정 제보자가 반복적으로 정확하면 → 신뢰 제보자 우대 (3막, 14번 문서)
