# 라맵 지도 API 무료 사용 타당성 딥다이브 (2026-08-25)

멀티에이전트 조사 (5 에이전트, 검색·문서조회 205회). 네이버/카카오/대안 스택의 공식 요금·약관 원문 및 공식 운영 답변 기준.

## 최종 결론

**무료 운영 가능. 단, 지도 표시가 아니라 '지오코딩 결과 저장'이 진짜 블로커였고, 아키텍처로 우회한다.**

## 종합 권고

■ 1순위 스택: "카카오맵 JS SDK(지도 표시·마커·클러스터링) + 공공데이터 지오코딩(행안부 juso.go.kr 좌표제공 API / LOCALDATA 음식점 인허가 좌표 / 상가업소 API, 부족분은 수동 핀 확정) + 좌표는 자체 DB에 영구 저장" 조합입니다.

■ 근거:
1) 비용 0원이 '구조적으로' 보장됨: 카카오는 결제수단(비즈월렛) 미등록 상태에서 무료 쿼터(지도 Web SDK 일 30만 로드 + 전체 API 합산 월 300만 건) 소진 시 429로 차단될 뿐 과금이 발생하지 않습니다. "월 몇만 원도 블로커"인 2인 무수익 프로젝트에서 유일하게 요금 폭탄이 원천 불가능한 구조입니다. 네이버(무료 월 600만 로드로 더 큼)는 콘솔 한도 설정으로 캡이 가능하지만 카드 등록이 필수라 차순위입니다.
2) 쿼터 여유: 성공 시나리오(월 50만 PV ≈ 일 1.7만 로드)도 일 한도의 6%, 월 한도의 17% 수준입니다. 과금 단위는 kakao.maps.Map() 객체 생성 1회=1건이며 마커·클러스터러 객체 생성과 타일 로드는 쿼터를 차감하지 않으므로(운영자 답변 확인) 마커 수백 개는 비용에 영향이 없습니다.
3) 지오코딩은 지도사 API로 하면 안 됨: '일괄 지오코딩 후 자체 DB 저장'은 네이버(Maps 약관 제7조 ⑪ "저장·DB화·재사용 엄격 금지" 명문)·카카오(데브톡 스태프 답변 3건, "실시간 호출만 허용, 제휴·유료로도 저장 검토 안 함")·VWorld("실시간 사용, 별도 저장 불가" 명시) 모두 약관 위반입니다. 쿼터가 남아도는 것과 무관하게 '저장'이 금지라는 게 핵심입니다. 따라서 좌표는 저장 제약이 없는 공공데이터에서 확보해야 하며, 이 구조(자체·공공 출처 좌표를 카카오 지도에 마커 표시 + 로컬 API는 실시간 보조 확인용)는 카카오 스태프가 동일 구조 질의에 명시적으로 허용 답변했습니다(devtalk.kakao.com/t/151052, 카카오 장소ID·place_url 저장도 허용). 수백 건 규모면 운영자가 지도에서 직접 핀을 확정하는 수동 보정도 현실적입니다(사용자 입력 데이터는 저장 허용).
4) SEO 대응: 지역x장르 SSR 페이지 수백 개는 지도 없이도 완결된 HTML(가게 리스트·주소·구조화 데이터)로 서버렌더링하고, 지도는 뷰포트 진입 시 lazy-load로 Map 객체를 생성하는 방식을 권합니다. 크롤러는 지도 로드를 소모하지 않고, 정적 지도 이미지의 사전 생성·캐싱은 양사 약관의 '결과 데이터 저장' 금지에 저촉될 소지가 커서 피해야 합니다. 카카오 정적 지도는 일 1,000건뿐이라 어차피 부적합합니다. 정적 이미지가 꼭 필요해지면 그때 네이버 Static Map(월 300만 건, 캐싱 없이 실시간 호출) 또는 자체 타일 렌더링을 추가하십시오.
5) 광고 수익화 호환: 카카오 스태프가 "AdSense 배너는 약관 위반 아님(상업적 활용 시 비즈앱 전환 권고)"이라고 공식 답변했습니다(devtalk 148272).

■ 설계 조건: 지도 레이어는 반드시 어댑터 패턴으로 추상화해 MapLibre GL 등으로 교체 가능하게 만드십시오. 네이버(2025-07 구 API 무료 종료)·카카오(2026-07 무료 쿼터를 계정당 첫 앱 1개로 축소) 모두 최근 2년간 무료 축소를 실행한 이력이 있어, 특정 지도사 종속은 이 프로젝트 최대의 구조적 리스크입니다. 좌표를 공공데이터로 자체 보유하는 이번 아키텍처는 지도사를 갈아타도 데이터가 살아남는다는 점에서 그 자체가 이식성 보험입니다.

## 리스크

1) 지오코딩 저장 금지(최대 리스크, 해소됨을 전제로 한 권고): 네이버 제7조 ⑪·카카오 스태프 답변·VWorld 가이드 모두 결과 좌표의 DB 저장을 금지합니다. 구현 시 "카카오/네이버 지오코딩을 편의상 배치로 돌려 저장"하는 유혹에 절대 넘어가면 안 됩니다. 적발 시 서비스 제공 중단 사유입니다(네이버 제8조: 기계적 대량 호출도 중단 사유).
2) 공공데이터 이용조건 미검증: juso.go.kr 좌표제공 API와 LOCALDATA·상가업소 API의 호출 한도·저장 허용 여부는 4개 조사 모두 원문 검증을 못 했습니다. 착수 전 반드시 각 약관 원문을 확인해야 합니다(권고 스택의 유일한 미확인 전제).
3) 무료 쿼터 축소 반복 추세: 네이버는 2025-07-01 구 지도 API 무료를 전면 종료했고, 카카오는 2026-07-21 무료 쿼터를 '계정당 첫 활성화 앱 1개'로 축소했습니다. 카카오도 "무료 쿼터는 추후 변경될 수 있다"고 명시합니다. 분기 1회 정책 재확인을 운영 루틴에 넣으십시오.
4) 카카오 첫 앱 한정 쿼터: 2인 팀 중 누구의 개발자 계정으로 앱을 활성화할지 미리 정해야 하며, 그 계정에서 라맵이 '첫 번째 활성화 앱'이어야 합니다. 그 계정의 다른 앱은 무료 쿼터가 없습니다.
5) 429 차단 = 가용성 리스크: 비용 리스크 0의 대가로, 트래픽이 급증하면 지도가 안 뜹니다(일 30만 로드 초과 시). 쿼터 사용량 모니터링과, 임계 접근 시 비즈월렛+금액 한도 설정으로 전환할지의 의사결정 기준을 미리 정해 두십시오.
6) 정적 지도 이미지 캐싱 금지: SEO용 이미지를 미리 생성·저장하는 것은 양사 '결과 데이터 저장' 금지에 저촉됩니다. lazy-load 동적 지도로 설계하면 회피됩니다.
7) 광고 수익화 시 비즈앱 전환: 카카오는 상업적 활용 시 비즈앱 전환을 권고하며, 이 과정에서 사업자등록이 필요할 수 있습니다. 2인 무수익 단계에서는 문제없으나 수익화 시점에 확인 필요.
8) 상표·표기 의무: 카카오 상표를 서비스명·로고에 사용 금지, 네이버는 로고·저작권 표기 제거 금지(제7조 ⑩). SDK 기본 표기를 건드리지 마십시오.

## Plan B (이행 경로)

단계적 이행 경로 3단계입니다. 좌표 데이터를 공공데이터로 자체 보유하는 권고 아키텍처 덕분에, 어느 단계로 옮겨도 POI DB는 그대로 살아남고 지도 렌더링 레이어만 교체하면 됩니다(어댑터 패턴 전제).

■ Plan B-1 (카카오 쿼터 초과가 일상화되거나 무료 정책 추가 축소 시): 네이버 클라우드 Maps로 전환. Dynamic Map 월 600만 건 무료로 한도가 카카오의 2배이고, 콘솔 '한도 및 알림 설정'(70%/90% 알림 + 무료 이용량 캡)으로 과금을 0원에 봉쇄할 수 있습니다. 대가는 카드 등록 필수와, 반드시 신규 'Maps' 상품으로 가입해야 한다는 것(구 AI NAVER API는 무료 0건). 개인 계정은 전화번호당 1개 대표 계정에만 무료 쿼터가 부여되므로 등록 계정을 미리 정할 것.

■ Plan B-2 (양대 지도사 모두 무료 축소·정책 변경 시, 최종 안전망): MapLibre GL JS + OpenFreeMap 벡터 타일 + supercluster 클러스터링. 가입·API키·한도 자체가 없고 상업 이용이 명시 허용되어 어떤 정책 변경에도 노출되지 않습니다. 지도 시각 품질(한국어 라벨·건물 밀도)은 국내 지도사 대비 열세지만, 라맵은 자체 POI가 주인공이고 베이스맵은 배경이므로 수용 가능한 트레이드오프입니다. OpenFreeMap의 SLA 부재가 문제되면 동일 스택(OpenMapTiles)을 자체 호스팅으로 이전할 수 있어 락인이 없습니다. 한국 품질 보강이 필요하면 VWorld WMTS 래스터 타일을 MapLibre에 얹는 변형도 가능하나, 운영키 심사·만료 연장(유선 절차)·타일 URL 키 노출 관리라는 운영 마찰을 감수해야 합니다.

■ 지오코딩 이행: 이미 공공데이터 기반이므로 지도사 정책 변경의 영향권 밖입니다. juso.go.kr이 막히면 VWorld 지오코더(일 4만 건, 단 실시간 사용 조건이므로 저장 목적엔 부적합)를 실시간 보조 확인용으로, 영구 저장용은 LOCALDATA·상가업소 공공데이터와 수동 핀 확정으로 대체합니다. Nominatim(OSM)은 저장이 오히려 의무(ODbL 표기 조건)라 최후 수단이 되지만 한국 주소 매칭 품질이 미검증입니다.

■ 전환 트리거 기준(미리 합의해 둘 것): (a) 일 로드가 무료 한도의 70%에 2주 연속 도달 → B-1 검토 착수, (b) 카카오/네이버 무료 정책 변경 공지 → 30일 내 B-2 프로토타입 검증, (c) 분기 1회 양사 요금·약관 페이지 정기 점검.

### 라맵 관점 판정
결론: '지도 표시'는 무료 운영 가능, '지오코딩 저장'은 불가 — 조건부 적합.
■ 비용 판정: 라맵의 트래픽(초기 월 수천~수만 PV, 성공 시 월 수십만 PV)은 Dynamic Map 무료 월 600만 건의 10% 미만이다. PV당 지도 로드 1회로 계산해 월 50만 PV여도 무료 한도의 8.3% 수준. 지역x장르 SSR 페이지 수백 개에 Static Map을 쓰더라도 월 300만 건 무료 한도 내에서 충분하다(단, 이미지 캐싱은 약관 위반이므로 매 요청 호출 전제 — 그래도 50만 PV면 한도 내). 콘솔 '한도 및 알림 설정'으로 무료 한도에 캡을 걸면 예기치 못한 과금을 구조적으로 차단할 수 있어 '월 몇만 원 블로커' 리스크는 제거된다. 결제수단(카드) 등록은 필수라는 점만 감수하면 된다.
■ 치명적 제약: 라맵의 핵심 요구인 '주소→좌표 일괄 지오코딩 후 자체 POI DB에 좌표 저장'은 Maps 약관 제7조 ⑪의 저장·DB화·재사용 금지에 정면으로 걸린다. 쿼터(월 300만 건)는 남아돌지만 약관상 결과를 저장할 수 없으므로, 네이버 Geocoding은 라맵의 용도에 사실상 쓸 수 없다.
■ 권고 구성: (1) 지도 표시·마커·클러스터링 = 네이버 Maps Dynamic Map(신규 'Maps' 상품으로 신청, 무료 월 600만 건, 한도 설정으로 캡). (2) 지오코딩 = 결과 저장이 허용되는 대체 수단 사용 — 예: 행정안전부 주소기반산업지원서비스(juso.go.kr) 좌표제공 API, 국토부 VWorld 등 공공 API(무료, 저장 제약이 상용 지도사 대비 완화됨 — 각 약관은 별도 확인 필요). 자체 확보한 좌표를 네이버 지도에 표시하는 것은 약관상 문제없다. (3) SEO용 정적 지도 이미지는 Static Map을 캐싱 없이 호출하거나, 캐싱이 꼭 필요하면 OSM 기반 자체 타일 등 대안 검토. (4) 반드시 신규 'Maps' 상품으로 가입할 것 — 구 AI NAVER API 지도는 2025-07-01부터 무료 쿼터가 전혀 없다. 개인 계정 기준 전화번호당 1개 대표 계정에만 무료 쿼터가 부여되는 점, 2인 프로젝트면 누구 계정으로 등록할지 미리 정할 것.

## 카카오맵

### 요약
카카오맵 API는 2026-07-21 정책 개편 이후에도 결제수단 등록 없이 무료 사용이 가능하다(초과 시 과금이 아니라 429 차단). 지도 JS SDK는 '무제한 무료'가 아니라 일 30만 건(kakao.maps.Map() 객체 생성 기준) + 전체 API 합산 월 300만 건 한도의 무료 쿼터이며, 무료 쿼터는 개발자 계정 기준 '첫 번째로 카카오맵 API를 활성화한 앱' 1개에만 제공된다. 로컬 REST API(주소→좌표 등)는 각 일 10만 건 무료. 그러나 결정적 제약은 약관이다: 데브톡 운영자 공식 답변(2026년 8월, 복수)에 따르면 로컬 API 응답 결과(좌표·주소·장소정보)의 DB 저장은 전면 불허되며 실시간 호출 형태로만 사용 가능하다. 즉 '지오코딩 후 좌표를 자체 DB에 저장'하는 라맵의 핵심 요구는 카카오 로컬 API로는 약관 위반이다. 자체 POI 데이터를 지도 위에 마커/클러스터로 표시하는 것 자체는 제약이 없다(마커·커스텀오버레이·MarkerClusterer 공식 제공, 객체 생성은 쿼터 미차감). 조사 시점: 2026-08-25.

### 라맵 관점 판정
조건부 가능 — 지도 표시는 무료로 충분하나, 지오코딩은 카카오로 하면 안 된다.
■ 지도 표시(마커 수백 개+클러스터링): 무료 운영 가능. JS SDK 일 30만 로드(페이지에서 지도 객체 생성 1회 = 1건), 월 300만 건 합산 한도. 월 수십만 PV(지도 포함 페이지 기준 일 1만~2만 로드)까지 무료 범위에 여유 있게 들어감. 월 300만 로드(일평균 약 10만)를 넘는 성공 시나리오에서도 초과분 0.1원/건이라 월 수만 원 수준. 결제수단 미등록이면 초과 시 차단이므로 비용 리스크는 0, 대신 가용성 리스크(트래�픽 급증 시 지도 미표시)가 있음. 단 '무제한 무료'라는 통념은 2026-07-21 개편 이후 사실이 아님(월 300만 합산 상한 + 계정당 첫 번째 앱만 무료). 2인 팀이면 한 명의 개발자 계정에서 첫 번째 앱으로 활성화해야 하며, 그 계정의 다른 앱은 무료 쿼터가 없음.
■ 지오코딩(주소→좌표 일괄 변환 후 DB 저장): 카카오 로컬 API로는 약관 위반. 쿼터(일 10만 건)는 넉넉하지만 응답 좌표의 DB 저장이 전면 불허이며 실시간 호출만 허용됨. 라맵처럼 자체 POI DB에 좌표를 영구 저장해야 하는 구조에서는 사용 불가. 대안: 좌표 저장이 허용되는 무료 지오코더(행정안전부 주소기반산업지원서비스 juso.go.kr, 국토교통부 VWorld 등)로 좌표를 확보해 자체 DB에 저장하고, 표시만 카카오맵 SDK로 하는 구성. 로컬 API 실시간 호출과 타사 유래 데이터의 지도 표시는 카카오도 허용한다고 답변함(151051).
■ SEO용 정적 지도 이미지: 부적합. 정적 지도 조회는 무료 일 1,000건뿐이고(초과 2원/건, 미결제 시 차단), 이미지를 서버에 저장·재서빙하는 것은 캐시 조항상 리스크. 수백 개 SSR 페이지에는 인터랙티브 지도 lazy-load(뷰포트 진입 시 Map 객체 생성)로 로드 수를 줄이는 편이 안전.
■ 종합: '카카오맵 SDK(표시·클러스터링) + 정부 무료 지오코더(좌표 확보·저장)' 조합이면 결제수단 등록 없이 월 0원 운영이 성립한다. 카카오 지오코딩 결과를 DB에 저장하는 설계는 약관 위반이므로 채택하면 안 된다. 조사 시점 2026-08-25 기준이며, 카카오가 "무료 쿼터는 추후 변경될 수 있다"고 명시하고 있어 정책 재확인 주기를 두어야 한다.

## 대안 스택 (VWorld/OSM/MapLibre/Mapbox/Google)

### 요약
결론: 라맵의 최적 무료 스택은 "MapLibre GL + OpenFreeMap(또는 VWorld 타일) + VWorld/Nominatim 지오코딩" 조합이다. (2) OSM 한국 커버리지는 주요 도시 도로망은 양호하나 POI·건물은 빈약 — 단, 라맵은 자체 POI DB를 얹으므로 베이스맵 용도로는 충분하며, OpenFreeMap이 API키·가입·한도 없이 무료(상업 이용 명시 허용)로 OSM 벡터 타일을 제공해 MapLibre와 바로 결합된다. Mapbox는 월 5만 로드 무료로 여유가 있으나 초과 시 $5/1천 로드 자동 과금 구조라 '성공 시' 시나리오에서 블로커가 된다. 조사 시점: 2026-08-25.

### 라맵 관점 판정
판정: 무료 운영 가능. 권장 스택은 "MapLibre GL JS + OpenFreeMap 벡터 타일(베이스맵) + 자체 POI DB 오버레이 + 클러스터링(MapLibre 내장/supercluster)"이다. 조건과 근거는 다음과 같다.

1) 베이스맵: OpenFreeMap이 무제한·무가입·상업 허용으로 월 수십만 PV까지 비용 0원. 유일한 리스크는 SLA 부재인데, 동일 스택(OpenMapTiles)을 자체 호스팅으로 이전 가능하므로 락인이 없다. 대안으로 VWorld WMTS 래스터 타일도 MapLibre/Leaflet에 얹을 수 있고 한국어 라벨·국내 지도 품질은 VWorld가 우위 — 단 운영키 심사·만료 연장·키 노출(타일 URL에 키 포함) 관리가 필요하다. OSM 한국 베이스맵은 주요 도시 도로망은 양호하나 건물·라벨 밀도가 국내 지도 대비 낮다(OSM 위키 한국 페이지 기준, POI는 "추가 작업 필요" 명시) — 라멘집 위치 파악용 배경지도로는 충분하나 시각 품질은 VWorld·네이버 대비 열세임을 감수해야 한다.

2) 지오코딩(초기 수백~수천 건 일괄 + 저장): 이것이 진짜 제약 지점이다. VWorld는 일 4만 건 무료로 용량은 충분하지만 "DB 저장 금지" 문언 때문에 좌표 영구 저장 목적에는 약관 위반 소지가 있다. Nominatim은 1 req/s 제한 하에 수천 건 일회성 배치가 가능하고 저장이 허용되나 한국 주소 매칭 품질이 미검증이다. 실무 권고: 행정안전부 주소기반산업지원서비스(juso.go.kr)의 좌표제공 API를 우선 검토하라(공공 무료, 이번 조사 범위 외라 한도·약관 미확인 — 착수 전 확인 필수). Google/Mapbox 지오코딩은 저장 제약(30일 캐싱/Permanent 유료) 때문에 부적합.

3) SEO용 서버렌더링 수백 페이지: 지도는 클라이언트에서 lazy-load하면 크롤러 트래픽이 맵 로드를 소모하지 않는다. 정적 지도 이미지가 꼭 필요하면 VWorld Static Map API(공개 한도 없음)가 유일한 무료 선택지다. Google Static Maps(월 1만 건)·Mapbox는 수백 페이지 x 크롤링+PV에서 한도를 넘는다.

4) 배제 판정: Google Maps는 2025-03 개편으로 Dynamic Maps 무료가 월 1만 로드뿐이라 '월 수만 PV' 시점에 즉시 과금 전환되고 카드 등록이 필수라 2인 무수익 프로젝트의 비용 블로커 요건에 정면으로 걸린다. Mapbox(월 5만 로드)는 초기에는 여유가 있으나 성공 시나리오(월 수십만 PV)에서 월 수십만 원대 과금이 발생하며 초과 시 차단이 아닌 자동 과금이라 리스크 통제가 안 된다. MapTiler 무료는 비상업 한정이라 광고 수익화 순간 위반이다.

필수 후속 확인 2건: (a) VWorld 이용약관 전문(로그인 후)과 운영키 신청 화면의 상업 이용 조건, (b) juso.go.kr 좌표제공 API의 한도·저장 허용 여부. 또한 VWorld 안정성 실사용 평판은 이번 세션에서 검증하지 못했으므로(검색 예산 소진) 프로토타입 단계에서 1~2주 타일 응답 지연·장애를 직접 계측할 것을 권한다.

### 라맵 관점 판정
결론: 조건부 무료 운영 가능. 단 아키텍처를 약관에 맞게 바꿔야 한다. (1) 지도 표시+마커+클러스터링: 카카오 지도 Web SDK 무료 일 30만 로드(월 환산 최대 ~900만)로 초기 월 수천~수만 PV는 물론 성공 시 월 수십만 PV(페이지당 1로드 가정 시 일 1~2만 로드 수준)도 무료 범위에 여유 있게 들어간다. 네이버 Dynamic Map 월 600만 로드 무료도 충분. 초과 시 카카오는 유료 미설정이면 429 차단(비용 리스크 0, 대신 서비스 중단), 네이버는 한도 설정으로 캡 가능 — 어느 쪽도 '모르는 새 몇만 원 청구' 시나리오는 방어 가능하다. 주의: 카카오 무료 쿼터는 계정당 첫 활성화 앱 1개뿐이므로 팀 계정 관리에 유의. (2) 지오코딩이 유일한 블로커: '초기 수백~수천 건 일괄 지오코딩 후 자체 DB 저장'은 네이버(약관 제7조 ⑪ 명문 금지)·카카오(공식 답변으로 저장 불허)·VWorld(저장 불가 명시) 모두 위반이다. 수백 건 규모면 무료 쿼터 안에서 '호출'은 공짜지만 '저장'이 금지라는 게 핵심. 합법 경로는 좌표를 저장 제약 없는 출처에서 확보하는 것: 행안부 주소기반산업지원서비스(juso.go.kr) 좌표제공 API, 지방행정인허가데이터(LOCALDATA)의 음식점 인허가 좌표, 공공데이터포털 상가업소 정보(좌표 포함) 등 — 단 이들 공공데이터의 개별 이용조건은 이번 조사에서 원문 검증을 못 했으므로 도입 전 확인 필요. 수백 건 규모면 지도에서 수동 핀 찍기(운영자가 직접 확정한 좌표는 '사용자 입력 데이터'로 저장 가능 — 카카오 공식 답변 근거)도 현실적 대안이다. (3) 자체 라멘집 POI DB를 지도 위에 표시하는 것 자체는 카카오 공식 확인으로 허용(네이버도 금지 조항 없음). (4) SEO용 지역x장르 페이지 수백 개: 정적 지도 이미지를 미리 생성·캐싱하는 것은 '결과 데이터 저장' 금지에 저촉될 소지가 크므로, 페이지 접속 시 실시간 호출로 처리해야 한다. 이 경우 카카오 정적 지도는 일 1,000건 무료라 부족할 수 있고, 네이버 Static Map 월 300만 건 무료가 유리하다. 다만 SSR 페이지에 동적 지도(JS SDK)를 lazy-load로 넣고 정적 이미지를 아예 쓰지 않는 편이 쿼터·약관 양쪽에서 가장 안전하다. (5) 광고 수익화: 카카오 공식 답변으로 배너 광고 허용(비즈앱 전환 필요 — 사업자등록 필요할 수 있음), 네이버도 금지 조항 없음. 종합 권고: 지도 표시=카카오 JS SDK(무료 쿼터 최대, 429 차단형이라 비용 리스크 0), 좌표 확보=공공데이터+수동 확정(지도사 지오코딩은 실시간 보조 확인용으로만), 무료 쿼터 축소가 반복되는 추세이므로 지도 레이어는 어댑터 패턴으로 추상화해 MapLibre+OSM 등으로 이전 가능하게 설계할 것.
