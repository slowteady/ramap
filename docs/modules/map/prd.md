# map 기획서

사용자는 홈(`/`)에서 지도·목록 바텀시트·매장 카드·필터·검색·마커로 라멘집을 장르와 지역으로 찾는다.
설계는 [design.md](design.md), 바뀐 기록은 이 파일의 GitHub 커밋 기록에 있다.

## 1. 왜 만드나

홈은 라멘집을 장르로 좁히고 지금 보는 지역에서 찾는 화면이다. 필터를 켠 지도 링크를 공유하는 것이 곧 라맵의 유통이다.

## 2. 범위

### 이번에 하는 것

- 홈 화면 구조(헤더 아래 필터 행·풀맵·상시 바텀시트)
- 마커·클러스터·라벨 겹침 처리
- 필터(축 칩·값 시트·토글 칩)와 URL 동기화
- 목록 시트·매장 카드
- 현위치
- 검색 오버레이
- 지도 실패 폴백
- 지도 SDK 어댑터

### 하지 않는 것

| 하지 않는 것 | 이유 또는 맡은 곳 |
|---|---|
| "이 지역 재검색" 버튼 | 재검토: 지도 뷰포트 런타임 API로 바꿀 때. 지금은 전량 SSG라 재검색 개념이 없다 |
| 값 칩 승격("축 칩 3 + 인기 값 칩 1~2") | 재검토: 출시 후 필터 로그에서 특정 값 사용이 압도적일 때. 승격 칩은 값 시트에도 중복으로 둔다 |
| 스타일 축을 지도 레이어/렌즈로 전환 | 재검토: 계보 태그 분포가 희소할 때 |
| 검색어 URL 공유(`?q=`)·검색 결과 리스트 화면·서버 검색 API | 재검토: 결과 리스트가 필요한 규모가 될 때 |
| 홈 헤더 풀폭 검색바 | 기각 — 필터 칩 행보다 검색이 앞서 보인다 |
| 인기 검색어 섹션 | 기각 — 실측 4곳 중 0곳이 사용한다 |
| 데스크톱 스플릿 뷰 | 재검토: 모바일 트래픽 비중을 확인한 뒤 |
| "지금 영업중" 필터, 실시간 대기 시간 | 기각 — [공통 결정](../../decisions/0009-no-live-open-status.md) |
| 매장 카드를 full로 펼쳐 상세 표시 | 기각 — 상세는 매장마다 고유 URL이 있어야 검색에 잡히는 SEO 단위라 `/shop/{id}` 페이지로 이동한다. 지도 SPA는 SEO를 못 한다 |
| 스프 계열별 마커 색(상위 값 고유색 + 묶음색, 색 + 약자) | 기각 — 스프는 8값 이상이라 지도 위 색 구분 한계(5~7색)를 넘고, 색약에서 병합되며, 사용자가 학습할 수 없다 |

## 3. 요구

마지막 번호: REQ-10

| ID | 요구 | 종류 | 요청 | 단계 | 확인 방법 |
|---|---|---|---|---|---|
| REQ-01 | 장르로 좁히기: 종류·국물·스타일로 라멘집을 거른다. 자가제면·본토직영 같은 특성, 새로 오픈한 곳, 안 가본 집, 저장한 곳만 보기도 된다 | 기능 | 없음 | 현재 | 없음 |
| REQ-02 | 지금 보는 지역 목록: 지도를 옮기면 그 범위의 매장 목록과 개수가 바로 바뀐다. 목록은 화면 중심에서 가까운 순이다 | 기능 | 없음 | 현재 | 없음 |
| REQ-03 | 빠른 확인 후 상세: 마커나 목록 항목을 누르면 지도를 떠나지 않고 매장 카드(영업시간·장르·편의·대표 메뉴·내 기록 버튼)를 본다. 카드에서 상세 페이지로 간다 | 기능 | 없음 | 현재 | 없음 |
| REQ-04 | 동네 감 잡기: 넓은 축척에서는 동네·구·시도 이름과 매장 수로 묶여 보인다 | 기능 | 없음 | 현재 | 없음 |
| REQ-05 | 내 주변: 버튼을 누르면 내 위치로 이동하고 거리가 보인다 | 기능 | 없음 | 현재 | 없음 |
| REQ-06 | 찾기: 매장명·장르·동네를 1글자부터 찾는다. 초성·영타·한 글자 오타도 찾는다 | 기능 | 없음 | 현재 | 없음 |
| REQ-07 | 공유·뒤로가기: 필터를 켠 지도와 선택한 매장을 링크로 공유한다. 뒤로가기로 카드·검색이 닫힌다 | 기능 | 없음 | 현재 | 없음 |
| REQ-08 | 내 기록이 보임: 저장한 곳과 완식한 곳이 지도 마커로 구분된다 | 기능 | 없음 | 현재 | 없음 |
| REQ-09 | 등록 진입: 지도에 없는 라멘집을 홈 버튼이나 검색 빈 결과에서 등록 요청한다 | 기능 | 없음 | 현재 | 없음 |
| REQ-10 | 지도 실패에도 사용: 지도가 안 뜨면 동네별 목록과 안내 배너가 대신 나온다 | 기능 | 없음 | 현재 | 없음 |

## 4. 규칙

| ID | 상황 | 규칙 | 예외 |
|---|---|---|---|
| P-01 | 위치 권한 요청 | 현위치 버튼을 누를 때만 요청한다. 진입 즉시 요청하지 않는다 | 없음 |
| P-02 | 필터를 바꿀 때 | 즉시 반영한다(Apply 버튼 없음). 적용할 때 뷰포트를 자동으로 옮기지 않는다 | 없음 |
| P-03 | 결과가 0건인 필터 값 | 비활성으로 둔다 | 없음 |
| P-04 | 지도 상태(필터·선택 매장·검색 오버레이·등록 시트) | URL이 원천이다. 뒤로가기와 공유를 함께 해결한다. 규칙은 [설계](design.md#url-쿼리)에 있다 | 없음 |
| P-05 | 영업 상태 표시 | 실시간 "영업중" 판정을 표시하지 않고 등록된 영업시간 정보만 보여 준다 → [공통 결정](../../decisions/0009-no-live-open-status.md) | 없음 |
| P-06 | 좌표 출처 | 공공데이터·수동 핀만 쓴다. 지도사 지오코딩 결과는 저장하지 않는다 → [공통 결정](../../decisions/0002-third-party-data-boundary.md) | 없음 |
| P-07 | 폐업·좌표 없는 매장 | 지도에 올리지 않는다 | 없음 |
| P-08 | 홈 화면 구성 | 홈은 스크롤 페이지가 아니다. SEO·콘텐츠 섹션을 지도 아래에 붙이지 않는다 | 없음 |
| P-09 | 초기 소셜프루프("N명 보는중") | 두지 않는다. 데이터가 빈약할 때 빈약함만 드러난다 | 없음 |
| P-10 | 마커 터치 타깃 | 44px이다 | 없음 |
| P-11 | 홈 UI | [ui design](../ui/design.md)과 `ramap-ui` 스킬의 UI 규율을 따른다 | 없음 |

## 5. 열린 문제

- [확인 필요: 과거 명세에 있었으나 지금 코드에 없는 아래 항목을 유지할까, 백로그로 내릴까? PO가 정한다]

| 항목 | 원래 근거 |
|---|---|
| 매장 카드 좌우 스와이프 = 인접 매장 순회 + 핀 하이라이트 | Yelp가 효과를 공식 보고했다. 지도 맥락을 유지한 비교 탐색이고, 밀집 상권 최대 줌 겹침의 해법으로도 지정됐다 |
| 0건 시 "가까운 N곳 보기" 완화 경로 | 필터 즉시 반영의 0건 처리 |
| 위치 권한 거부 시 동네 선택 대체 | 위치 권한 UX |
| 매장 카드 사진 스트립(대표 1 + 서브 2, 직접 촬영·허락분만) | 바텀 카드 벤치마크(오늘의집) |
| 매장 카드 대표 메뉴 1~3개 | 지금은 1개만 표시한다 |
