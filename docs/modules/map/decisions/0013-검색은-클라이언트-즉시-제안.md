# 검색은 클라이언트 즉시 제안

## 맥락

매장명·장르·동네로 매장을 찾아 지도로 보내는 검색이 필요했다. 전 데이터(지도 핀, 수십~수백 규모)가 이미 클라이언트에 있다.

## 결정

- 서버·API·디바운스 없이 클라이언트 전량에서 **1글자부터 즉시 제안**한다.
- 결과 화면은 없다. 제안 선택이 곧 필터 적용·지도 이동이다.
- 입력 전 화면 = 장르 바로가기 + 최근 검색. 인기 검색어 없음.
- 제안은 유형을 구분한다: 장르(아이콘 + 매장 수) / 매장(상호 + 동네). 하이라이트는 완성부 볼드.
- 매칭: 부분문자열 + 초성. 접두 일치 > 부분 일치. 같은 날 확장 — 영타 → 한글 변환, 매칭 필드에 지점명·세부 국물·대표 메뉴 추가, 동네 이동 제안, 결과가 없을 때 오타 1자 폴백.
- 빈 결과 = "검색 결과가 없어요" + 신규 장소 등록 유도.
- 최근 검색은 선택한 매장·장르·동네만 저장한다(미완성 입력 미저장).

## 근거

2026-09-01 카카오맵·캐치테이블·네이버지도·오늘의집 모바일 웹 실측(스크린샷 26장).

1. 입력 화면 = 카테고리 바로가기 + 최근 검색 두 섹션. 인기 검색어 사용 0/4.
2. 자동완성은 1글자부터. 제안 유형 구분은 캐치테이블 벤치마크(카테고리: 아이콘 + 매장 수 "라멘 189" / 매장: 상호 + 주소). 완성부 볼드는 캐치·오늘의집.
3. 결과: 대형 지도사는 리스트 전환, 캐치는 지도 + 시트 유지 + 검색어 → 카테고리 필터 자동 매핑. 라맵은 이미 지도 + 시트라 캐치 패턴 직접 참고.
4. 빈 결과 = "검색결과가 없어요" + 신규 장소 등록 유도 버튼(카카오·네이버 공통).
5. 부분 매칭은 네이버식 중간 매칭.
6. 초성 추출·영타 변환은 es-hangul — [공통 결정](../../../decisions/0004-라이브러리-도입-트리거.md). 편집거리 폴백만 자체 구현.

## 버린 안

- 서버 검색 API·디바운스.
- 인기 검색어 섹션.
- 검색 결과 리스트 화면 — 규모가 커지면 재검토.
