# SEO 하이브리드 구조 — 지도는 인터랙션용, 검색 유입은 SSR 랜딩망

## 맥락

라맵 홈은 카카오맵 기반 클라이언트 지도다. 지도 화면만으로는 검색엔진이 읽을 텍스트·링크가 없고, 크롤러가 지도 SDK를 불러 쿼터를 쓰는 문제도 있다.

## 결정

- **"지도 SPA는 SEO를 못 한다. 트래픽 엔진은 별도의 SSR 리스트 페이지망이다."** 홈 지도는 인터랙션용 클라이언트 화면이고, 지역×택소노미 SSR(실제로는 빌드 타임 SSG) 리스트 페이지망이 1급 시민이다
- 지역×장르 페이지는 지도 없이 완결된 HTML(리스트·주소·구조화 데이터)로 렌더한다
- 리스트 템플릿: H1 연도 신선도("마포 돈코츠 라멘 맛집 N곳 (2026)") + SSR 카드 리스트 + 인근 지역·관련 장르 교차 링크 + 택소노미 용어 해설 FAQ(차별 자산)
- SSR 페이지의 지도는 facade + 클릭 시 로드(뷰포트 진입 lazy-load만으론 불충분), CLS 방지 컨테이너 크기 명시. 크롤러가 지도 쿼터를 쓰지 않게 한다
- 정적 지도 이미지 사전 생성·캐싱 금지(약관) → [공통 결정](../../../decisions/0002-타사-플랫폼-데이터-경계.md)

## 근거

- 13번 UI 설계원칙 E절(2026-08-26 조사, BP 6에이전트 중 SEO 하이브리드 담당): Zillow·Yelp·Tripadvisor·Tabelog·Airbnb 5개 서비스가 모두 같은 결론. Tabelog는 라멘 도메인 직접 선례
- 09번 기술타당성 "SEO 설계 원칙"(근거: `docs/research/2026-08-25-라맵-지도API-무료사용-타당성조사.md`)
- 2026-09-05 SEO 딥리서치 재확인: Airbnb·Zillow·호갱노노 전 사례에서 색인은 지도와 분리된 텍스트 표면이 담당 — 지도는 SEO에 0 기여. 승부처는 본문 텍스트량이 아니라 URL 설계·메타·내부 링크 메시(다이닝코드 리스트는 SSR 50자로도 1위, ItemList 완비 + 태그 링크 메시). 라맵은 SSR이라 다이닝코드가 CSR로 놓치는 서버 렌더 앵커텍스트까지 가져갈 수 있다

## 버린 안

- 지도 SPA 하나로 SEO까지 처리 — 위 5개 서비스 모두 쓰지 않는 방식
- SSR 페이지에 지도 위젯 즉시 로드(`loading=lazy`만) — 크롤러 쿼터 소모·CLS
