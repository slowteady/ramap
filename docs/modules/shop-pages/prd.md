# shop-pages 기획서

검색 유입자와 지도 사용자가 매장 상세 페이지와 검색 유입용 랜딩(지역·지역×장르·계보·장르 가이드)에서 라멘집을 확인한다. 이 모듈은 이 페이지들의 색인·구조화 데이터·사이트맵까지 맡고, 아래 요구는 모두 현재 단계다.
설계는 [design.md](design.md), 바뀐 기록은 이 파일의 GitHub 커밋 기록에 있다.

## 1. 왜 만드나

사용자마다 들어오는 길과 해야 하는 일이 다르다.

| 사용자 | 들어오는 길 | 해야 하는 일 |
|---|---|---|
| 검색 유입자 | 구글·네이버 검색 결과 | 매장 이름, "○○ 폐업했나?", 지역×장르("성수 츠케멘"), 장르 정의("니보시 라멘", "라멘 종류")에 대한 답을 지도 없이 첫 화면에서 얻는다 |
| 지도 사용자 | 홈 지도 → 매장 선택 | 상세에서 정체(상호·동네·장르)·영업시간·위치·메뉴를 확인하고 길찾기·공유·주소 복사를 한다 |
| 입문자 | 상세·필터·리스트의 장르 링크 | 장르가 무엇인지 읽고, 그 장르를 내는 실매장으로 넘어간다 |
| 마니아 | 계보 랜딩 | 계보(이에케·지로계) 전국 매장과 자기 완식 여부를 한눈에 본다 |

### 목표 검색 쿼리

검색 유입은 아래 우선순위로 노린다.

| 순위 | 쿼리 | 이유 |
|---|---|---|
| 1 | 브랜드 "라맵" | 웹사이트 영역이 최상단에 오는 유일한 쿼리 유형이다 |
| 2 | 장르 쿼리("니보시 라멘"·"이에케 라멘"·"라멘 종류") | 매장과 연결된 디렉토리가 없는 공백이다 |
| 3 | 지역×장르 롱테일("성수 츠케멘"·"홍대 이에케") | 다이닝코드가 다루지 않는다 |
| 비타깃 | "성수 라멘" 같은 광의 쿼리 정면 승부 | 리스트 페이지 품질이 쌓인 뒤 다시 검토한다 |

## 2. 범위

### 이번에 하는 것

| 화면 | 주소 | 요구·규칙 |
|---|---|---|
| 매장 상세 | `/shop/{id}` | REQ-01~09, P-01~02 |
| 지역, 지역×장르 | `/area/{지역}`, `/area/{지역}/{장르}` | REQ-10~11, P-03 |
| 계보 랜딩 | `/style/{계보}` | REQ-12, P-04 |
| 장르 가이드 | `/guide`, `/guide/{장르}` | REQ-13~14, P-05~06 |
| 검색 유입(SEO) | 색인 대상 페이지 전체 | REQ-15~18, P-07 |

### 하지 않는 것

| 하지 않는 것 | 이유 또는 맡은 곳 |
|---|---|
| 신규 오픈 전용 페이지(`/new`) | 네이버·배민·Google·타베로그·ramendb 모두 신규 오픈을 홈·검색 안의 배지·필터로 보이고 전용 페이지를 두지 않으며, 월 1~2곳 규모에선 대부분 빈 상태라 NEW 칩과 "새로 오픈" 필터로 대신한다 |
| 상세 메뉴 탭·전화 버튼 | [결정](decisions/0003-shop-detail-structure.md) |
| 실시간 "영업 중" 표시 | [공통 결정](../../decisions/0009-no-live-open-status.md) |
| 계보 랜딩 진행률 바 | [records 기획서](../records/prd.md) |
| 역 거리("○○역 도보 N분") | 시트에 필드가 없고, 파트너 태깅 확장 후보다 |
| 요일별 영업시간 | 시트는 단일 문자열이고, 요일별 편차 매장이 늘면 스키마를 확장한다 |
| 사이트맵 분할(`generateSitemaps`)·크롤 예산 최적화 | 약 2k 페이지라 규모에 맞지 않는다(50k 한도의 4%, 크롤 예산은 100만+ 대상 기법) |
| SearchAction·UA 분기 동적 렌더링 | SearchAction은 폐지됐고, UA 분기는 전량 SSG라 불필요하고 권장되지 않는다 |
| 백링크 구매 | 네이버가 명시적으로 제재한다 |
| 가이드 대표 매장 수동 지정 | 운영 부담이 크고 기준이 불투명해, 순위는 데이터에서 계산한다 |
| 네이버 `nmap://` 좌표 길찾기 | 앱 전용이라 앱 미설치 폰·PC에서 열리지 않으므로, 도착지 정확도보다 도달성을 앞세워 이름 검색 + 지도 중심 좌표로 대신한다 |

## 4. 규칙

| ID | 상황 | 규칙 | 예외 |
|---|---|---|---|
| P-01 | 매장 상세 상호 옆 NEW 칩 | 오픈 90일 이내 매장에만 붙인다 → [map 설계](../map/design.md#신규-오픈-표시) | 없음 |
| P-02 | 폐업·이전 매장의 상세 페이지 | 폐업·이전이 검증된 매장은 그 사실을 제목·본문에 밝히고 페이지를 유지한다 → [결정](decisions/0012-closed-shop-page-indexing.md) | 검증되지 않은 폐업 매장은 페이지가 없다 |
| P-03 | 지역×장르 페이지 생성 | 영업 매장 3곳 이상인 조합만 페이지가 생긴다 | 미달 조합은 404이고 지도 필터로만 본다(홈 canonical `/`이 쿼리 변형을 흡수한다) |
| P-04 | 계보 랜딩 대상 | 맛 계보(taste: 이에케·지로계)만 대상이다 | 없음 |
| P-05 | 장르 가이드 대상 | 국물 8(돈코츠·쇼유·시오·미소·돈코츠쇼유·니보시·토리파이탄·탄탄멘)과 맛 계보 2(이에케·지로계)가 대상이다 | 자가제면·본토직영 같은 특성 태그는 맛 계열이 아니라 대상이 아니다 |
| P-06 | 장르 가이드 대표 매장 | 최대 5곳을 보이고, 넘으면 지도로 전체 보기를 둔다 | 없음 |
| P-07 | 색인 제외 | 정보가 거의 없는 매장 페이지·매장 3곳 미만 지역 페이지·기타 장르 조합은 색인에서 빼고 페이지는 유지한다 → [결정](decisions/0008-noindex-criteria.md) | 없음 |

P-03의 근거: 0~2곳짜리 얇은 페이지를 대량 색인하면 검색엔진 품질 평가가 깎이고, 구글 faceted navigation 지침도 결과 없는 조합은 404로 둔다.

## 5. 열린 문제

### 제약

| 제약 | 근거 |
|---|---|
| 지역×장르 조합은 "매장 3곳 이상 + 검색 수요 실재"일 때만 늘리고, 검색 순열식 확장은 하지 않는다 | 구글 scaled content 판정은 목적·가치·탐색 계층을 보므로 순열식 확장은 위험하고, 검색 수요는 실측 전이라 지금은 3곳 규칙만 적용한다 |
| 평점(`aggregateRating`)·리뷰 마크업은 실데이터 전까지 쓰지 않는다 | 근거 없는 평점 마크업은 구글 스팸 정책상 수동 조치 대상이다 |
| FAQ 마크업은 새로 늘리지 않고, 기존 잔존은 유지한다 | 구글·네이버 모두 FAQ 리치결과를 폐지했고, 기존 두 곳은 무해해 둔다 |
| 정적 지도 이미지의 사전 생성·캐싱과 지오코딩 결과 저장을 하지 않는다 | [공통 결정](../../decisions/0002-third-party-data-boundary.md) |
| 타사 로고를 쓰지 않고, 인스타 링크는 텍스트로만 둔다 | [공통 결정](../../decisions/0002-third-party-data-boundary.md) |
| SSR 페이지에 지도 위젯을 바로 띄우지 않고 지금은 "지도에서 보기" 링크만 두며, 넣는다면 facade + 클릭(또는 뷰포트 진입) 시 로드와 CLS 방지 컨테이너 크기 명시를 지킨다 | [결정](decisions/0001-seo-hybrid-structure.md) |
| 라이트 모드 고정이고, 계보 랜딩의 어두운 헤더는 다크 모드가 아니라 고정 색 블록이다 | 카카오맵에 다크 타일이 없다 → [ui 기획서](../ui/prd.md) |
| 홈은 순수 지도 앱으로 두고 SEO용 링크 섹션을 넣지 않으며, 랜딩 발견은 sitemap·robots가, 링크 그래프는 랜딩 간 교차 링크가 맡는다 | 몰입형 지도 홈에 스크롤 푸터는 맞지 않아 구현 후 PO가 기각했고, 홈의 링크 주스는 포기한다 |
