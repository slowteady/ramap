# product 기획서

라맵은 **한국 라멘을 장르로 찾는 지도**다. 라멘 덕후는 돈코츠·쇼유·이에케이·지로계·츠케멘처럼 실제로 고르는 기준 그대로 전국 라멘집을 걸러 보고, 라맵은 이를 검증된 라멘 전문 DB로 받친다.
MVP의 MUST 기능과 SHOULD의 신규 오픈·장르 가이드는 모두 충족됐고, 공유 이미지는 범위 밖으로 뺐다.
설계는 각 모듈의 design.md([문서 색인](../../README.md))에 있고, 바뀐 기록은 이 파일의 GitHub 커밋 기록에 있다.

## 1. 왜 만드나

라멘 소비자가 장르·속성(돈코츠/쇼유/이에케이/지로계, 면 굵기, 국물 농도, 주문 방식 등) 기준으로 라멘집을 찾을 수단이 없다. 네이버·카카오는 이 축을 주지 않고, 정보는 커뮤니티·블로그·인스타그램에 파편화돼 있다.

문제는 "맵 부재"가 아니라 "분류 체계 부재"다. 네이버 지도에서도 "라멘"은 검색된다. 그래서 만들 것은 지도 UI가 아니라 택소노미와 데이터다. 지도 UI로는 네이버와 정면 대결하지만, 택소노미·데이터는 네이버가 만들 이유가 없는 축이라 이길 수 있다.

### 문제가 실재한다는 증거

- DC 라멘 미니갤러리 유저가 자작 지도(「라멘 뉴비가 서울 라멘 지도 만들었어!」)와 자작 영업 변동 사이트(라멘 투데이, 공지 고정·제보 루프 작동)를 만들었다. 커뮤니티가 스스로 도구를 만들고 유지한다
- 장르별 라멘 연말결산 블로그가 있다. 돈코츠/쇼유/시오/츠케멘 분류가 이미 커뮤니티 표준어다
- 타베로그 도쿄 라멘 1위 '라멘야 시마'가 서울에 진출했다. 시장 성숙 신호다
- 라멘갤 최근 6개월 글 25,195건 중 질문·추천 요청이 31%이고, 그중 장르·스타일 21%·지역 15%·웨이팅 14%다 ([라멘갤 페인포인트 조사](research/2026-10-28-ramengal-pain-points.md))

진짜 경쟁자는 네이버 지도 저장 리스트 + 구글 마이맵 + 인스타그램 해시태그 + 갤러리 스크랩이다. 라맵은 이들이 구조적으로 못 하는 것, 곧 정규화된 장르 필터·크로스 리스트 통합·신규 오픈 추적을 해야 한다.

### 쓰는 사람

초기 타겟은 코어 덕후(한국형 라오타)다. 근거는 [0004](decisions/0004-core-ramen-otaku-target.md)에 있다.

| 쓰는 사람 | 규모 | 하는 일 | 불편 강도 / 기여 의향 | 위치 |
|---|---|---|---|---|
| A. 코어 덕후 (한국형 라오타) | 수백~수천 명 | DC 미니갤·트위터 라멘계에서 장르 용어를 구사하고, 신규 오픈을 추적하고, 원정 방문하고, 자기 리스트를 가진다 | ◎ / ◎ | 초기 타겟 |
| B. 라이트 애호가 | 수만 명 | 월 2~4회 소비하고 "츠케멘이 뭔지 아는" 수준이며, 소비만 하고 기여하지 않는다 | ○ / △ | 2차 — SEO 롱테일로 자연 유입 |
| C. 일반 소비자 | 수십만 명 | "근처 라멘 맛집" 검색으로 충분하고 네이버로 해결한다 | △ / ✕ | 타겟 아님 |

페르소나:

> 20대 후반~30대 중반, 수도권 거주. 월 4회+ 라멘 소비, 신규 오픈을 트위터·갤러리에서 추적. 네이버 저장 리스트에 라멘집 30개+.
> 불편: 저장 리스트에 장르 구분이 안 되고, 남의 리스트와 합칠 수 없고, 신규 오픈을 놓친다.
> 원하는 것: 내 기준(장르·지역·미방문)으로 필터 가능한, 신뢰할 수 있는 전국 라멘 DB.

### 기존 대안과 다른 점

| 기존 대안 | 못 하는 것 | 라맵 |
|---|---|---|
| 네이버·카카오 지도 | "라멘" 검색만 되고 장르 축이 없다 | 장르·면·국물·주문방식 필터 |
| 라멘GPS | 데이터가 얕고 검증이 없어 신뢰가 0이다 | 라오타 감수 태깅 + 제보·검증 루프 |
| 갤러리 자작 지도 | 갱신되지 않고 필터할 수 없다 | 지속 갱신되는 구조화 DB |
| 인스타그램 저장·블로그 | 파편화돼 검색할 수 없다 | "성수 이에케이" 조합 검색 |

해자는 세 가지다.

1. 택소노미: ramendb 30년 분류 체계의 한국화(제공 형태 × 국물 계열 × 계보·특성 태그 3축)다. 네이버가 못 베끼는 게 아니라 만들 이유가 없는 축이다
2. 검증된 태깅: 장르 판별은 라오타만 할 수 있다. 데이터 자체가 해자다
3. 신규 오픈 추적: 덕후의 최대 관심사이자 재방문 훅이다

### 이름과 포지셔닝

- 포지셔닝은 "일본에 30년 있던 것(ramendb)의 한국 첫 버전"이다
- 서비스명은 라맵, 도메인은 ramap.kr이다. 브랜드는 라멘 전용으로 둔다(라오타에게 "내 것"으로 읽힌다)
- "누들맵"은 종합 포털로 읽혀 1막 정체성이 흐려지고, 한국인은 "누들"로 검색하지 않아 버렸다
- 선정 근거는 [0001](decisions/0001-ramen-genre-map.md)에 있다

### 프로젝트 목표 (수익 아님)

1. 트래픽 경험: SEO 기반 오가닉 유입을 만들고 성장시켜 본다
2. 자아실현·완주: 실제로 사람들이 쓰는 것을 만들어 운영한다
3. 포트폴리오: 실유저·실트래픽·데이터 파이프라인·의사결정 기록을 갖춘 운영 프로젝트를 남긴다

### 성공 지표

수익 대신 세 지표로 판정한다([무수익 구조](#비용지속-구조)라 매출로는 판정할 수 없다). 각 지표는 제품의 핵심 장치(SEO·제보 루프·커뮤니티 유통) 하나씩에 대응한다.

1. 월 오가닉 검색 유입: SEO 엔진이 작동하는지 본다
2. 유저 제보 건수: 3층 데이터 루프가 작동하는지 본다
3. 커뮤니티 자발 언급: 갤러리·트위터에 "라맵"이 등장하는지 본다. 죽은 선행자 라멘GPS가 0이었던 지표다

되면 달라지는 것: 월 오가닉 검색 유입·유저 제보 건수·커뮤니티 자발 언급, 세 지표로 잰다.

### 만드는 팀

| 역할 | 책임 |
|---|---|

| 도메인 파트너 1명 (라오타, 공동 제작자) | 택소노미 설계·장르 태깅·커뮤니티 침투를 맡는다. 페르소나 A 본인이라 검증 접근 경로다 |

### 성장 전략

- 뼈대: 코어 라오타(SOM, 수백~수천 명)를 잡으면 장르를 아는 라이트층(SAM, 수만 명)이 SEO로 따라온다. 일반 소비자는 목표가 아니다 ([시장 규모](research/2026-08-26-market-size.md))
- 유통 채널: DC 라멘 미니갤러리다. 공개는 검증된 플레이북(파딱 사전 허락·세줄요약 겸손 톤·광고 없음·제보 마찰 최소화·댓글 피드백 반영)으로 한다 → [0009](decisions/0009-ramen-today-and-gallery-launch.md)
- 라멘 투데이: 경쟁하지 않고 제휴를 우선한다 → [0009](decisions/0009-ramen-today-and-gallery-launch.md)
- 실행 순서:
  1. 파트너가 갤러리에서 눈팅 + 후기 기여로 계정 신뢰를 쌓는다
  2. 데이터를 300곳+ 태깅 완료 상태로 준비한다(P-01·P-02). 공개 시점에 "빈 껍데기"면 한 방에 끝난다. 갤에서 화제인 라멘집의 누락도 같은 신뢰 결함이다([백로그](../../backlog.md) D-11)
  3. 파딱 허락을 받고 "(파딱허락o) 장르별로 라멘집 찾는 지도 만들어봤습니다"로 공개한다. 광고 없음을 밝히고 제보 폼을 안내한다
  4. 직후 며칠간 댓글 피드백을 즉시 반영하는 모습을 보여준다. 초기 신뢰의 승부처다
  5. 갤러리 공개로 신뢰를 확보한 뒤 라멘 투데이 운영자에게 상호 링크를 제안한다
- 현재 갤러리 소개 글은 게시 전이다(PO 몫, [백로그](../../backlog.md) G-03)

## 2. 범위

MVP가 검증할 핵심 가설은 "**라오타는 장르 필터가 있는 검증된 라멘 DB에 반응한다**(방문하고, 커뮤니티에 공유하고, 제보한다)"이다. 이 검증에 필요 없는 기능은 넣지 않는다.

### 이번에 하는 것

| 기능 | 우선순위 | 요구 | 화면 | 지금 상태 |
|---|---|---|---|---|
| 라멘 DB | MUST | REQ-01, P-01, P-02 | 없음 | 충족 — `data/shops.json` 1,332행(영업 1,289·폐업 43), 전국 |
| 지도 뷰 + 장르 필터 | MUST | REQ-02 | 홈 `/` (카카오 JS SDK, 마커·클러스터링) | 충족 |
| 매장 상세 (SSR) | MUST | REQ-03, REQ-04 | `/shop/[slug]` | 충족 |
| 지역×장르 페이지 | MUST | REQ-05, REQ-06 | `/area/[area]`, `/area/[area]/[genre]` | 충족 |
| 제보·수정 폼 | MUST | REQ-07, P-05 | `/report`, 검수 `/admin` | 충족 |
| 완식·저장 기록 | MUST | REQ-08, P-04 | 마이 `/me` | 충족 |
| 신규 오픈 | SHOULD | REQ-09, P-03 | 전용 페이지 없이 지도 NEW 마커·목록 NEW 칩·홈 "새로 오픈" 필터 칩 | 충족 |
| 장르 가이드 | SHOULD | REQ-10 | `/guide`, `/guide/[slug]`, 계보 페이지 `/style/[lineage]` | 충족 |

### 하지 않는 것

확장 후보와 다음 기능은 [백로그](../../backlog.md)가 단일 원천이다(제품 기능 P-*, 확장 버티컬 X-*). 백로그의 P-* 번호는 이 문서 4절의 규칙 ID와 다른 번호 체계다.

아래 항목은 핵심 가설 검증에 필요 없거나 라오타의 신뢰를 해친다. 순위·광고·줄 길이 근거는 [라멘갤 페인포인트 조사](research/2026-10-28-ramengal-pain-points.md) §3·§5에 있다.

| 하지 않는 것 | 이유 또는 맡은 곳 | 다시 볼 때 |
|---|---|---|
| 공유 이미지 (참여 2단): 단일 짤(완식 총수·내 지도·최다 장르·인생 라멘 3~4곳), 소목록 완주 인정증, 연말 "올해의 라멘" | SHOULD였지만 범위 밖으로 뺐고 [백로그](../../backlog.md) P-04·P-07이 맡는다. 지금은 매장 상세 링크 공유만 한다 | 없음 |
| 리뷰·평점 | 유저가 없을 때 빈 칸만 보이는 콜드스타트 함정이다 | 3막 이후 |
| 예약·주문 연동 | 수익이 목표가 아니다 | 하지 않음 |
| 네이티브 앱 | SEO가 트래픽 엔진이라 웹을 우선한다 | 하지 않음 |
| 어워드 | 1막 범위 밖이다 | 3막 |
| 면 확장 버티컬(평양냉면·우동·소바) | 1막(라멘) 정체성을 우선한다 | 2막 |
| 수익화 | 아래 [비용·지속 구조](#비용지속-구조)를 따른다 | 켜지 않음 |
| 가게 단일 순위·티어 | 갤 안에서도 티어리스트끼리 같은 가게가 S급에서 꼴찌까지 갈려 신뢰 논쟁을 부르므로, 장르별 대표 라멘집 모음처럼 기준을 밝힌 큐레이션으로 답한다 | 없음 |
| 광고·협찬 노출 | 라오타의 후기·순위 불신(바이럴·인플루언서·다중 계정 의심)과 광고 반감이 강하다 | 없음 |
| 실시간 줄 길이 | 정적 데이터로 알 수 없다 | 사용자 제보가 쌓이면 |

## 5. 열린 문제

### 가정

- 한국 라멘 전문점은 수백~천 개 규모로 추정한다. 그래서 사업이 아니라 트래픽 있는 사이드 프로젝트가 현실적 상한이다 ([시장 규모](research/2026-08-26-market-size.md))

### 제약

- 타사 플랫폼 데이터는 아웃바운드 링크·사실 기록까지만 쓴다 → [타사 플랫폼 데이터 경계](../../decisions/0002-third-party-data-boundary.md)
- 기술 스택 → [기술 스택과 축소형 FSD](../../decisions/0001-tech-stack-lite-fsd.md)

### 비용·지속 구조

라맵은 수익 없이 비용 구조로 지속한다. 운영비를 연 2만 원(도메인) + 팀의 시간으로 묶어 사이드 프로젝트 사망 원인 2위인 서버비 부담을 없애면, 수익 압박 없이 무기한 지속할 수 있다.

| 항목 | 금액 |
|---|---|
| 지도 API | 0원 (카카오 JS SDK 무료 쿼터, 초과 시 차단형이라 과금이 불가능한 구조) |
| 호스팅 | 0원 (Vercel 무료 티어) |
| 도메인 ramap.kr | ~2만 원/년 |
| 데이터 구축·유지 | 팀의 시간 |

수익화(애드센스 배너, 어워드 스폰서)는 설계만 하고 켜지 않는다. 애드센스는 카카오 약관 위반이 아님을 공식 확인했지만(상업 활용 시 비즈앱 전환 권고), 월 10만 PV여도 월 수만 원 수준이라 UX를 해칠 가치가 없다. 광고·협찬은 노출하지 않는다.
