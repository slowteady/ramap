# UI 요구사항

디자인 시스템·정보 구조·공통 UI 규율이 지켜야 할 요구.

## 사용자 요구

| 요구 | 내용 |
|---|---|
| 이동 중 탐색 | 휴대폰 브라우저에서 한 손으로 라멘집을 찾고 본다. 모바일웹이 기준 화면 — 사용 맥락이 이동 중 탐색이고, 구글은 모바일 버전으로 랭킹을 판정한다(모바일 퍼스트 인덱싱) |
| 데스크톱 무붕괴 | 데스크톱에서도 깨지지 않는다. 콘텐츠 페이지는 중앙 단일 컬럼 |
| 길 잃지 않기 | 메뉴가 적고, 어느 2뎁스 페이지에서든 뒤로가기 한 번으로 돌아간다. 이력 없이 검색으로 착지해도 홈으로 나갈 수 있다 |
| 누를 곳이 보임 | 색이 있는 곳 = 누를 수 있는 곳. 상태는 색이 아니라 반전·보더·명도로 구분된다 |
| 신뢰할 수 있는 화면 | 기본값 티(AI티)가 없고 "라맵 화면"으로 식별된다 |
| 터치 가능 | 터치 타깃 44px 이상. 상태를 색에만 의존하지 않고 형태·크기를 병행(접근성) |
| 지도 실패에도 쓸 수 있음 | 지도를 쓰는 화면은 지도 로드 실패 시 리스트 + "지도를 불러오지 못했어요" 배너로 대체된다 — 발견 서비스에서 지도 결함은 치명 결함(망고플레이트 사망 원인) |

## 범위

- 디자인 토큰(색·radius·타이포·간격·폰트)과 사용 규율
- 정보 구조: 내비게이션·라우트 맵·헤더 형태
- 공통 라벨(유저 기여·수정 진입)
- 화면 품질 게이트(AI티 방지)와 안티패턴 목록
- UI 코드 작성 규율(`ramap-ui` 스킬)

## 제약

- 토큰 외 값 금지 — Tailwind 임의값(`w-[13px]`) 금지, `@theme` 토큰 유틸만, CSS 파일 추가 금지([결정](decisions/0001-design-token-rules.md))
- 유채색은 라멘 레드 1색 + 시맨틱 그린뿐([결정](decisions/0001-design-token-rules.md))
- 라이트 모드 고정, `.dark` 블록 금지 — 카카오맵에 다크 타일이 없어 지도가 주인공인 화면에서 UI만 어둡게 할 수 없다
- 타사 로고 사용 금지([공통 결정](../../decisions/0002-third-party-data-boundary.md))
- 이모지 아이콘 금지 — lucide 단일 세트
- 앱 없음

## 범위 밖

| 항목 | 재검토 조건 |
|---|---|
| 데스크톱 스플릿 뷰(좌 리스트 + 우 지도) | 모바일 트래픽 비중 확인 후. 표준 패턴이지만 선투자할 트래픽 근거가 없다 |
| 랭킹·어워드 메뉴 | 3막 — 데이터 축적 후 |
| 네이티브 앱 | 만들지 않는다 — 모바일웹이 기준 화면 |
| 메뉴 다수 구성 | 기각 — 얕은 메뉴만 늘어난다(BlackRoad 19개 메뉴 반면교사) |
| 2뎁스 헤더의 로고·홈 링크 | 기각 — 뒤로가기의 홈 폴백으로 충분 |
| 신규 등록 라벨 "제보하기" | 기각 — 수정·폐업과 구분되지 않는다 |
