# records 기획서

라멘 순례자가 완식·저장을 기록하고, 완식 사진·한줄평을 남기고, 마이에서 쌓인 기록을 모아 본다. 기록하려면 카카오 로그인과 약관 동의를 거친다.
지금 1단(완식·저장 기록, 날짜, 사진·한줄평, 마이)과 3단 가운데 완식 코멘트 선택 공개가 구현돼 있다.
설계는 [design.md](design.md), 바뀐 기록은 이 파일의 GitHub 커밋 기록에 있다.

## 1. 왜 만드나

라멘 순례자가 이미 하는 행위(완식 = 스프까지 비움)를 기록으로 남기고, 쌓인 기록을 한눈에 보여 준다. 게임이 아니라 기록으로 읽혀야 한다. "완식"은 게임 용어가 아니라 라멘 문화 안의 실천 용어라 그대로 기록이 된다.

참여 장치는 3단 사다리(1단 기록·축적, 2단 정산·공유, 3단 집단 산출)로 쌓는다 → [단계](#단계)

기록 체계는 형태를 바꾸지 않고 그 위에 쌓기만 한다. 정체성이 된 장치를 걷어내면 서비스가 무너진다(Foursquare/Swarm 3위→146위). 그래서 새 장치는 P-14를 통과해야 한다 → [딥리서치 보고서](research/2026-08-26-engagement-retention-research.md)

되면 달라지는 것: 라멘 순례자가 이미 하는 완식이 기록으로 남고, 쌓인 기록을 한 화면에서 본다.

## 2. 범위

### 이번에 하는 것

- 완식·저장 기록과 완식 날짜
- 완식 사진·한줄평(선택 부가물)과 공개 동의
- 마이: 완식·저장·제보 탭, 기록 뷰어
- 카카오 로그인, 약관 동의, 로그아웃, 회원탈퇴

### 단계

참여 장치는 3단 사다리로 쌓는다. 근거는 [딥리서치 보고서](research/2026-08-26-engagement-retention-research.md)(서비스 30여 곳 조사)다.

- 1단 본체는 기록·축적이다. 이미 하는 행위를 기록하고 한 화면에 쌓아 보여 준다. 사용자 규모와 무관하게 작동한다.
- 진행·목표(유한한 목록 + 보이는 빈칸 + 달성 가능한 크기)는 1단·2단에 얹는다.
- 2단 본체는 정산·공유다. 기록을 이야기로 돌려주면 유저가 배급망이 된다. 2단 규칙(P-17~P-20)의 근거도 같은 보고서다.
- 3단은 집단 산출이다. 개인 기록의 총합이 공공재가 되고, 파생 문화는 커뮤니티가 만든다. 3단 규칙(P-21~P-23)은 랭킹·보상으로 미끄러지지 않게 미리 막아 둔 것이다.
- 경쟁·지위 장치는 어느 단계에도 넣지 않는다 → [하지 않는 것](#하지-않는-것)

| 단계 | 담는 것 | 현재 |
|---|---|---|
| 1단 | 완식·저장 기록, 날짜, 사진·한줄평, 마이 | 구현 |
| 1단 | 장르×지역 소목록 진행률("서울 이에케 4/7") | 보류(P-15, P-16) |
| 2단 | 공유 이미지: 단일 이미지, 완주 인정증, 연말 "Year in 라멘". 정산·공유는 영원히 무료 | 미구현 |
| 3단 | 완식 횟수 집계 공개, 가게 어워드, 완식 코멘트 선택 공개 | 코멘트 선택 공개만 구현(공개 동의 + 선검수) → [사진·한줄평](decisions/0015-optional-photo-note-review.md) |

## 4. 규칙

| ID | 상황 | 규칙 | 예외 |
|---|---|---|---|
| P-01 | 완식 횟수를 셀 때 | 완식 1杯 = 가게 1곳 방문 1회다. 재방문은 가게별 횟수를 늘린다 → [단위](decisions/0003-visit-unit-one-bowl.md) | 이미 완식한 가게에 사진을 더 남기는 것은 횟수를 바꾸지 않는다 |
| P-02 | 기록 상태를 정할 때 | 상태는 완식과 저장 두 가지다. "별로였다" 같은 부정 상태는 없다 → [기록 모델](design.md#기록-모델) | 한 가게에 둘이 함께 있을 수 있다(완식한 가게도 다시 가려고 저장해 둔다) |
| P-03 | 완식을 누른 뒤 | 기록 시트에서 확인해야 +1이 된다. 시트를 닫으면 아무것도 기록되지 않고, 되돌리기는 없다 → [기록 시트](decisions/0021-visit-confirm-in-sheet.md) | 없음 |
| P-04 | 완식에 평가나 메모를 받을 때 | 별점은 받지 않는다([금지 목록](decisions/0002-gamification-ban-list.md)). 메모는 선택 한줄평 30자다 | 없음 |
| P-05 | 한줄평을 쓸 때 | 한줄평은 사진이 있을 때만 쓸 수 있다 → [부가물](decisions/0015-optional-photo-note-review.md) | 없음 |
| P-06 | 사진을 넣고 완식할 때 | 업로드가 성공해야 완식이 기록된다. 사진만 빠진 완식이 조용히 남지 않게 한다 | 없음 |
| P-07 | 사진·한줄평을 보여 줄 때 | 다른 사람에게는 "매장 페이지에 소개돼도 좋아요"에 동의하고 운영자 검수를 통과한 것만 보인다 | 본인은 제출 즉시 보되 "검토 중" 표시가 붙는다 |
| P-08 | 지도 마커를 그릴 때 | 사진·한줄평 유무로 지도 마커가 바뀌지 않는다 | 없음 |
| P-09 | 공개할 사진을 고를 때 | 라멘이 주인공이고, 직접 찍은 사진이고, 다른 사람 얼굴이 안 나와야 한다 | 없음 |
| P-10 | 비로그인 사용자가 완식·저장을 누를 때 | 카카오 로그인 시트를 띄운다. 무인증 연타로 횟수를 부풀리거나 기기마다 기록이 갈리지 않게 하기 위해서다 | 없음 |
| P-11 | 가입을 확정할 때 | 가입은 약관 동의로 확정된다(소셜 인증 ≠ 가입). 동의 전에는 기록할 수 없다 → [로그인·약관 동의](design.md#로그인약관-동의프로필) | 없음 |
| P-12 | 가입할 때 닉네임을 정할 때 | 닉네임은 라멘 테마로 자동 할당된다. 변경 기능은 없다 | 없음 |
| P-13 | 마이에 기록이 없을 때 | 소급 기록(이미 가 본 집) 유도는 빈 상태 문구까지만 한다 → [하지 않는 것](#하지-않는-것) | 없음 |
| P-14 | 새 참여 장치를 더할 때 | "10년 유지 가능한가 + 나중에 뗄 수 있는가"를 통과해야 한다 → [딥리서치 보고서](research/2026-08-26-engagement-retention-research.md) | 없음 |

| P-18 | 2단 공유 이미지의 구성 | 완식 총수(구체 숫자) + 내 라멘 지도 + 장르 분포·최다 장르 + 내 인생 라멘 3~4곳이다. 기발함이 숫자를 대체하면 실패한다 | 소목록을 완주하면 인정증 특별판이다. 라멘랠리 완주 인정증에서 경품·제휴만 뺀 형식이다 |
| P-19 | 2단 공유의 갈래 | 상시 내보내기와 연말 "Year in 라멘" 두 갈래다. 남과 비교하는 건 유저가 골라 내보낼 때만이고 상시 비교 피드는 두지 않는다 | 없음 |
| P-20 | 정산·공유의 가격 | 정산·공유는 유료화하지 않는다(영원히 무료). 정산은 배급망이라 유료화하면 배급망이 끊긴다 | 없음 |
| P-21 | 3단 집계 | 집계는 점수 랭킹이 아니라 완식 횟수다. 가중 포인트는 산출식 논쟁을 부르고 횟수는 논쟁이 없다 | 없음 |
| P-22 | 3단 어워드 | 어워드는 유저 순위가 아니라 가게에 주는 집단 산출물이다. 개별 보상은 없고 가중치는 공개하지 않는다(보상이 걸리면 허위 체크인이 늘어난다) | 없음 |
| P-23 | 3단 리뷰 | 리뷰는 별점 집계가 아니라 완식 기록에 붙은 개인 코멘트의 선택 공개다. 인증된 것만 공용 콘텐츠로 올린다 | 없음 |

## 5. 열린 문제

- 가정: 이용약관·개인정보 처리방침은 법률 검토 전 초안이다.
- 가정: 프로필 이미지는 두지 않는다(닉네임 텍스트만).
- 제약: 애플 로그인을 추가하면 Supabase identity linking 설정이 필요하다.
- 제약: 정지 유저 처리는 없다. 공개 콘텐츠가 늘면 다시 본다.
- 소목록 진행률을 다시 열 때 정할 것: 목록 단위·노출 위치·인정증. 근거 조사는 [지도·상세 검수 조사](../../research/2026-10-27-map-detail-review.md) F-A다. "0에서 출발하지 않게"(부여된 진전) 장치도 이때 함께 본다.
