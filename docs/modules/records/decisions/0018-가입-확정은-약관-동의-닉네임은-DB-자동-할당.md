# 가입 확정은 약관 동의, 닉네임은 DB가 라멘 테마로 자동 할당

## 맥락

keeper(keeper-app·keeper-backend)의 계정 라이프사이클을 이식하되 Supabase(자체 서버 0)에 맞춰 번역하기로 했다(PO 결정). keeper 원문은 [keeper 계정 정책 노트](../notes/keeper-계정-정책.md).

## 결정

| keeper | 라맵 (Supabase) | 강제 지점 |
|---|---|---|
| 카카오 토큰 검증·교환 | `signInWithOAuth({provider:"kakao"})` | Supabase |
| access/refresh 회전·세션 테이블 | Supabase Auth 내장(PKCE·자동 갱신) — 이식 불필요 | Supabase |
| signupToken 중간 상태 | 불가능(OAuth 완료 = `auth.users` 생성). "미동의 상태"로 번역: profiles는 즉시 생성되되 `agreed_at null` | — |
| 가입 확정 = 약관 동의 | `agreed_at is null`이면 약관 동의 시트 → 동의 시 `agreed_at`·약관/방침 버전 기록 | 클라 게이트 + RLS(records·record_photos 쓰기에 `agreed_at is not null`) |
| 소셜 프로필 스코프 미요청 | 동일 — 카카오 닉네임·프로필사진 요청 안 함. 표시명은 `profiles.nickname` 단일 | 카카오 콘솔 |
| 이메일 중복 소셜 감지 | 카카오 단일이라 해당 없음 | — |
| 정지 유저 | 미도입 | — |

닉네임:

- 할당 시점은 `auth.users` AFTER INSERT 트리거(`handle_new_user`) — Supabase는 중간 상태가 없어 생성 시점으로 옮겼다. 동의 전엔 닉네임이 노출되지 않아 체감은 같다.
- 생성은 전부 DB 안에서(`generate_nickname`, 레이스 안전). keeper 로직 1:1: 형용사+명사 랜덤 → 중복이면 10회 재시도 → 4자리 접미사 10회 → 폴백.
- 사전은 라맵 테마: 형용사는 keeper 톤, 명사는 라멘 어휘("따뜻한차슈" 같은 조합).
- 닉네임 변경은 후속(쿨다운 트리거와 함께 개방). 그 전까지 update 정책으로 불변을 강제한다.

## 근거

- keeper 원칙: 소셜 인증 ≠ 가입, 가입 확정 = 약관 동의 시점.
- 도메인 정체성 + 사전 출처 명확(라멘 명사).
- 미동의 이탈 시 다음 로그인에 재노출, 기록 쓰기는 클라+RLS 양쪽에서 차단.

## 버린 안

- 닉네임을 동의 시점에 클라이언트가 생성 — 레이스, 중간 상태 불가.
- 카카오 이름 폴백 표시 — 프로필 스코프를 받지 않으므로 제거.
