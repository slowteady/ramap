# records 요구사항

완식·저장 기록, 완식 사진·한줄평, 마이, 카카오 로그인·약관 동의가 지켜야 할 조건.

## 목적

- 라멘 순례자가 이미 하는 행위(완식 = 스프까지 비움)를 기록으로 남기고, 쌓인 기록을 한눈에 보여준다. 게임이 아니라 기록으로 읽혀야 한다 → [참여 설계 3단 사다리](decisions/0001-three-step-engagement-ladder.md)
- 기록 체계는 형태를 바꾸지 않고 그 위에 쌓기만 한다. 새 장치는 "10년 유지 가능한가 + 나중에 뗄 수 있는가"를 통과해야 한다 → [참여 설계](decisions/0001-three-step-engagement-ladder.md)

## 기록

- 완식 1杯 = 가게 1곳 방문 1회. 재방문은 가게별 횟수를 늘린다 → [단위](decisions/0003-visit-unit-one-bowl.md)
- 상태는 완식과 저장 두 가지. 부정 상태는 없다. 한 가게에 둘이 함께 있을 수 있다(완식한 가게도 다시 가려고 저장해 둔다) → [상태](decisions/0005-record-states-visit-save.md), [기록 모델](design.md#기록-모델)
- 완식마다 날짜를 저장한다(첫 완식일·최근 완식일). 화면에 보이지 않아도 2단 연말 정산의 원료다 → [기록 모델](design.md#기록-모델)
- 완식은 기록 시트에서 확인해야 +1이 된다. 시트를 닫으면 아무것도 기록되지 않는다. 되돌리기는 없다 → [기록 시트](decisions/0021-visit-confirm-in-sheet.md)
- 완식 기록 삭제는 마이 기록 뷰어에서 확인을 거쳐서만 한다.
- 별점은 받지 않는다([금지 목록](decisions/0002-gamification-ban-list.md)). 메모는 선택 한줄평(30자)이다.
- 기록은 소실되면 안 된다 — 계정에 서버 저장한다 → [서버 저장](decisions/0012-server-records-login-merge.md)

## 완식 사진·한줄평

- 사진·한줄평은 선택 부가물이다. 한줄평은 사진이 있을 때만 쓸 수 있다 → [부가물](decisions/0015-optional-photo-note-review.md)
- 사진을 넣었으면 업로드가 성공해야 완식이 기록된다(사진만 빠진 완식이 조용히 남지 않게).
- 다른 사람에게는 "매장 페이지에 소개돼도 좋아요"에 동의하고 운영자 검수를 통과한 것만 보인다. 본인은 제출 즉시 보되 "검토 중" 표시가 붙는다.
- 사진·한줄평 유무로 지도 마커가 바뀌지 않는다.
- 공개 사진 기준: 라멘이 주인공 / 직접 찍은 사진 / 다른 사람 얼굴이 안 나오게.
- 이미 완식한 가게에 사진을 더 남길 수 있다. 이것은 횟수를 바꾸지 않는다.
- 사진의 위치정보(EXIF)는 지운다.

## 계정

- 열람은 로그인 없이 전부 열려 있다. 기여(기록)만 계정이 필요하다 → [열람 개방](decisions/0011-kakao-login-open-browsing.md)
- 기록하려면 로그인해야 한다 → [로그인 필수](decisions/0013-records-require-login.md)
- 로그인은 카카오 하나다. 카카오 프로필(이름·사진)은 요청하지도 수집하지도 않는다.
- 가입은 약관 동의로 확정된다(소셜 인증 ≠ 가입). 동의 전에는 기록할 수 없다 → [로그인·약관 동의](design.md#로그인약관-동의프로필)
- 닉네임은 가입 시 라멘 테마로 자동 할당된다. 변경 기능은 없다.
- 회원탈퇴를 제공한다(법적 필수). 탈퇴하면 기록과 사진이 모두 지워진다 → [탈퇴](decisions/0017-drop-export-account-deletion.md)
- 로그아웃해도 서버 기록은 남는다.

## 마이

- 내 완식·저장을 모아 본다. 검색 노출 안 함(noindex).
- 세 번째 탭 "기여"에서 내 제보·완식 사진의 검수 결과를 본다 → [report 요구사항](../report/requirements.md#기여-결과-피드백)
- 첫 진입에 온보딩이나 소급 기록 강제 화면을 두지 않는다. 소급 유도는 빈 상태 문구까지만 → [온보딩 폐기](decisions/0016-drop-onboarding-map-first.md)

## 금지 (전 단계)

스트릭·연속 방문·주간 목표 / 공개 리더보드·자리 경쟁 / 배지·레벨·칭호(완주 인정증만 예외) / 자기 설정 수치 목표·뒤처짐 표시 / 별점 집계 리뷰 / 물리 경품·점포 제휴·조건부 보상 / 타인 기록 상시 피드·프로필 비교 / 초대제·가치 경험 전 계정 요구 / 전국 전체 도감을 유일 목표로 / 정착한 기록 체계의 철거·개편 → [금지 목록](decisions/0002-gamification-ban-list.md)

## 단계별 범위

| 단계 | 내용 | 현재 |
|---|---|---|
| 1단 | 완식·저장 기록, 날짜, 사진·한줄평, 마이 | 구현 |
| 1단 | 장르×지역 소목록 진행률("서울 이에케 4/7", 10곳 내외) | 보류 — 목록 단위·노출 위치·인정증 미정 → [진행률 보류](decisions/0024-defer-progress-display.md) |
| 2단 | 공유 이미지: 단일 이미지, 완주 인정증, 연말 "Year in 라멘". 정산·공유는 영원히 무료 | 미구현 |
| 3단 | 완식 횟수 집계 공개, 가게 어워드, 완식 코멘트 선택 공개 | 코멘트 선택 공개만 구현(공개 동의 + 선검수) → [사진·한줄평](decisions/0015-optional-photo-note-review.md) |

### 2단 공유 이미지

근거는 [딥리서치 보고서](research/2026-08-26-engagement-retention-research.md).

- Wrapped식 멀티 장면이 아니라 단일 이미지다 — 갤러리는 "짤 한 장" 문화.
- 구성: 완식 총수(구체 숫자 — 기발함이 숫자를 대체하면 실패한다) + 내 라멘 지도 + 장르 분포·최다 장르 + 내 인생 라멘 3~4곳.
- 소목록을 완주하면 인정증 특별판. 라멘랠리 완주 인정증에서 경품·제휴만 뺀 형식이다.
- 상시 내보내기와 연말 "Year in 라멘" 두 갈래다. 남과 비교하는 건 유저가 골라 내보낼 때만이고 상시 비교 피드는 두지 않는다.
- 정산·공유는 유료화하지 않는다. 정산은 배급망이라 유료화하면 배급망이 끊긴다.

### 3단 집단 산출

랭킹·보상으로 미끄러지지 않게 미리 막아 둔다.

- 집계는 점수 랭킹이 아니라 완식 횟수다. 가중 포인트는 산출식 논쟁을 부르고 횟수는 논쟁이 없다.
- 어워드는 유저 순위가 아니라 가게에 주는 집단 산출물이다. 개별 보상은 없고 가중치는 공개하지 않는다(보상이 걸리면 허위 체크인이 늘어난다).
- 리뷰는 별점 집계가 아니라 완식 기록에 붙은 개인 코멘트의 선택 공개다. 인증된 것만 공용 콘텐츠로 올린다.
- H-index류 파생 지표는 만들지 않고 집계 데이터를 공개해 커뮤니티가 만들게 둔다.
- 다시 볼 후보: pairwise 서열(Beli식), 텍스트 → 시각화(Sakenowa식, 대량 축적 후), 가게 N회 완식 자동 표시.

## 다른 모듈과의 약속

- 승인된 한줄평은 매장 한줄소개(태그라인)를 사람이 고를 때 원천이 된다 → [data 설계](../data/design.md)
- 완식·저장 상태는 지도 마커와 필터에 쓰인다 → [map 설계](../map/design.md)
- 사진 검수 화면은 report 모듈의 /admin에 있다 → [report 설계](../report/design.md)
- 데이터 경계(타인 사진 게재 금지 등) → [타사 플랫폼 데이터 경계](../../decisions/0002-third-party-data-boundary.md)

## 확인 안 된 전제

- 이용약관·개인정보 처리방침은 법률 검토 전 초안이다.
- 애플 로그인을 추가하면 Supabase identity linking 설정이 필요하다.
- 정지 유저 처리는 없다 — 공개 콘텐츠가 늘면 다시 본다.
- 프로필 이미지는 두지 않는다(닉네임 텍스트만).
