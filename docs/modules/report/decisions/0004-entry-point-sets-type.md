# 유형 선택 화면 없이 진입점이 제보 유형을 정한다

## 맥락

기존 `/report` 단일 페이지는 유형 3탭(새 라멘집/정보 수정/폐업·휴업)을 한 폼에 몰았다. 홈 → `/report` 이동이 뚝 끊기고 뒤로가기 어포던스가 없었고, 수정·폐업 제보에 매장을 특정할 수단이 없었다.

## 결정

- 유형을 고르는 화면을 두지 않는다. **진입점이 유형을 결정한다.**
  - 새 라멘집 등록: 홈 필터 행 [라멘집 등록], 검색 결과 없음 화면 [라멘집 등록하기]
  - 정보 수정: 매장 상세의 "잘못된 정보가 있나요?" 일급 행(질문형 리드 + 셰브런). 매장 미지정 수정 경로는 만들지 않는다
- **폐업은 별도 유형이 아니라 수정 항목 중 하나**다.
- 폼은 현재 화면 위로 아래→위 슬라이드하는 풀스크린 시트. URL 쿼리(`?report=new` / `?report=edit&shop={id}`)로 관리해 브라우저 뒤로가기 = 닫기.
- `/report` 라우트는 `/?report=new` 리다이렉트로 호환한다.
- 완료 화면은 시트 안에서 전환한다.

## 근거

2026-08-31 실측(카카오맵·네이버플레이스·구글맵·캐치테이블·다이닝코드 모바일 웹):

1. 유형을 먼저 고르는 선행 화면을 두는 서비스는 없다. 수정·폐업은 장소 상세에서, 신규 등록은 검색 결과 없음 화면(카카오)·지도 메뉴(구글)에서 진입. 상세에 신규 등록을 두는 곳은 없다.
2. 폐업은 수정 항목 체크리스트의 한 항목 — 캐치테이블 "매장이 폐점했어요" 체크박스, 구글 "폐업하거나 이 위치에 없음", 다이닝코드 폐업신고 체크박스.
3. 상세 진입점은 정보 섹션 하단의 일급 행 + 질문형 리드 — 캐치테이블 "잘못된 정보가 있나요? / 수정이 필요하거나 폐점한 매장이라면 알려주세요!" + 셰브런. 더보기 메뉴에 숨기지 않는다.
4. 폼 공통 구성: 항목 다중 체크 + 선택 자유 텍스트 + 사진 첨부 + "검수 후 반영" 안내.
5. 모바일 작성 플로우는 페이지 이동이 아니라 아래→위 풀스크린 시트 전환이 관례.

## 버린 안

- `/report` 페이지 + 유형 3탭.
- 홈 상시 시트와 같은 vaul Drawer — 중첩되므로 쓰지 않음.
