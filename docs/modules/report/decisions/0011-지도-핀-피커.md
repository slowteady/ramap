# 등록 위치는 중앙 십자선 핀 피커로 조준한다

## 맥락

[뷰포트 중심 첨부](0010-지도-위치는-뷰포트-중심-첨부.md)는 시트를 열기 직전 지도 중심을 그대로 스냅샷했다. 시트가 지도를 완전히 덮어 사용자가 조준할 수 없었고, 운영자는 그 좌표를 믿을 수 없었다.

## 결정

| 항목 | 선택 |
|---|---|
| 조준 | 중앙 십자선 고정 + 지도 이동 |
| 확정 UI | 시트가 아닌 하단 고정 바(88px) [이 위치로 지정] + 좌상단 [취소] |
| 조준점 | 뷰포트 중심이 아니라 바를 뺀 가시영역의 위에서 40% 지점 |
| 주소 표시 | 없음, 좌표만. 조준점 위에 입력한 가게 이름 뱃지 |
| 폼 상태 | 언마운트 금지 — 폼을 숨기고 같은 시트 안에 피커를 얹는다 |
| 지도 인스턴스 | 새로 만들지 않고 뒤에 떠 있는 홈 지도를 그대로 노출 |
| 최소 줌 | 진입 시 강제 확대, 이후 소프트 게이트(임계보다 축소되면 확정 비활성 + "조금 더 확대해 주세요") |
| 정밀도 보조 | 현재위치 버튼만 |
| 라우팅 | `?report=new&pick=1`(열기 push, 닫기 replace → 시스템 뒤로가기는 피커만 닫음) |

## 근거

- 카카오맵·네이버지도 제보는 앱 전용 — 모바일 웹에 진입점 없음(실측). 구글맵은 한국에서 주소 대신 좌표(DMS)+Plus Code만 표시 — 지도 데이터 반출 제약으로 우리와 같은 성격. OSM 노트는 반면교사(패널이 위 55%를 먹어 지도가 45%로 눌린 채 정확한 위치를 요구).
- 핀 드래그는 손가락이 목표를 가리고, 탭-투-드롭은 하단 바에 가린 영역을 못 찍는다.
- 조준점을 위로 올리는 이유: 엄지·바에 안 가리게.
- 역지오코딩 저장 금지. 링크 우선 모델이라 핀은 운영자가 동네를 찾아갈 힌트다.
- 폼 draft가 훅 상태에 있어 언마운트하면 날아간다. 형제 오버레이면 보존 로직 0줄.
- 지도 SDK 인스턴스 중복·relayout·타일 재요청 회피. 기존 마커가 보여 중복 제보가 줄어드는 부수 효과.
- 하드 줌 블록은 "왜 안 움직이지?" 혼란을 낳는다.
- 제보자는 대개 가게 앞에 있다(현재위치). 주소 검색은 카카오 로컬 API가 필요해 제외.

## 버린 안

- 뷰포트 중심 스냅샷 토글.
- 핀 드래그, 탭-투-드롭, 주소 검색, 역지오코딩 주소 표시.
