# 폐업·휴업 제보는 2차 확인 전 반영 금지

## 맥락

제보 유형마다 잘못 반영했을 때의 피해가 다르다.

## 결정

| 유형 | 규칙 |
|---|---|
| 새 라멘집 | 실존 확인(인스타·전화) → 시딩과 동일한 태깅 절차. 확신도 `추정`으로 시작 가능 |
| 정보 수정 | 교차 확인 후 반영. 장르 이견은 라오타가 최종 판정 |
| 폐업·휴업 | **2차 확인(전화·인스타·인허가 diff) 전 반영 금지** |

행정 데이터(인허가 diff)에서 감지한 폐업은 제보가 아니므로 이 규칙 대상이 아니다 → [data 설계](../../data/design.md)

## 근거

오폐업 표시는 매장에 실해를 끼치는 유일한 케이스라 가장 엄격하게 다룬다. 판정 절차는 `.claude/skills/closure-verification`. 원문: `docs/planning/16.제보운영플로우.md`.
