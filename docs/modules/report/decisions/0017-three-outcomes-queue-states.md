# 제보 처리 결과는 반영함·중복·반려 3종, 큐는 대기/처리됨

## 맥락

처리 상태가 open/done 둘뿐이라 반영·중복·반려를 구분하지 못했다.

## 결정

- 처리 결과 3종: **✓반영함 / 중복 / 반려** — `reports.resolution`·`note`·`resolved_at`.
- 반영함·중복은 접힌 "메모 추가"로 메모를 남길 수 있다.
- 반려는 사유 필수: 칩(확인 불가·라멘집 아님·정보 불일치·스팸) 또는 직접 입력.
- 반려 버튼은 반영함과 떨어뜨려 오른쪽 끝에 둔다.
- 큐는 **대기 / 처리됨** 필터로 나눈다. 처리됨 카드는 읽기 전용.
- 다시 열기는 ⋯ 메뉴 안에 두고, **status만 바꿔 결과·메모·처리일을 보존**한다. 재처리하면 덮어쓴다.
- 사진 검수도 같은 문법: ✓승인 / 반려(사유 칩: 라멘이 안 보임·본인 촬영 아님·부적절 + 직접 입력).

## 근거

- 결과 세분: Linear Triage(Accept·Duplicate·Decline), MapRoulette(고침·이미 반영·문제 아님).
- 메모 동반: Linear Triage. 반려 사유 필수: Stack Overflow·Discourse.
- 버튼 배치: NN/g — 결과가 다른 버튼을 붙여 두지 않는다.
- 처리 항목 분리·재오픈: Intercom Open/Closed. 다시 열기는 ⋯ 메뉴: Intercom.
- 이력 보존: GitHub·Zendesk.

## 버린 안

- open/done 2상태만.
- 전체 처리 이력 테이블 — 제보량이 늘 때 도입.
