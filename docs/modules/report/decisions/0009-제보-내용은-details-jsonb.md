# reports 스키마는 그대로, 유형별 구조는 details jsonb에

## 맥락

진입점별 두 폼(신규·수정)이 서로 다른 구조의 데이터를 보낸다.

## 결정

- `reports` 테이블 컬럼을 늘리지 않는다. 유형별 구조는 `details jsonb`에 적재한다.
- `shop_name`·`location`은 사람이 읽는 값: 신규는 가게 이름과 첫 링크(없으면 핀 좌표), 수정은 대상 매장의 상호와 주소/동네(없으면 id).
- `type`은 `new`/`edit` 두 값만 쓴다. 폐업은 `edit`의 항목이다(check 제약의 `closed` 값은 미사용 잔존).

## 근거

대시보드·검수 화면에서 사람이 바로 읽을 값은 컬럼에, 나머지는 유연한 jsonb에. 스키마 마이그레이션 없이 폼을 바꿀 수 있다.
