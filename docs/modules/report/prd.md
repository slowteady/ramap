# report 기획서

사용자는 로그인 없이 새 라멘집 등록과 정보 수정을 제보하고, 파트너(라오타)는 앱 안 /admin에서 제보와 완식 사진을 검수한다. 제보자는 마이 "제보" 탭에서 자기 제보의 결과를 본다.
설계는 [design.md](design.md), 바뀐 기록은 이 파일의 GitHub 커밋 기록에 있다.

## 1. 왜 만드나

라맵은 제보의 입구를 최대한 열고, 출구는 전건 검수한다 → [입구 개방·출구 검수](decisions/0001-open-intake-full-review.md), [익명 제보](decisions/0002-anonymous-reports.md). 검수·반영의 주 담당은 파트너(라오타)이고, 판정과 반영 사이에 개발자가 끼지 않는다.

### 성공 지표

검수 결과 피드백의 성과는 PostHog 이벤트로 잰다(이벤트 정의는 [platform 설계](../platform/design.md#이용-통계)의 `EventMap`).

| 지표 | 뜻 | 재는 법 |
|---|---|---|
| 결과 확인율 | 결과가 나온 로그인 제보 중, 제보자가 "제보" 탭에서 그 결과를 본 비율 | "제보" 탭 열람 이벤트(새 결과 수 포함) |
| 재제보율 | 결과를 확인한 제보자가 30일 안에 다시 제보한 비율 | 탭 열람 이후 `report_submitted` |
| 로그인 제보 비율 | 전체 제보 중 로그인 상태로 낸 비율로, 익명 완료 화면의 로그인 유도 효과를 본다 | `report_submitted`에 로그인 여부 속성 |

## 2. 범위

### 이번에 하는 것

- 제보 폼: 새 라멘집 등록, 정보 수정
- 검수 화면 /admin: 제보 처리, 완식 사진 검수
- 검수 결과 피드백: 완료 화면 문구, 마이 "제보" 탭, 새 결과 점 표시

### 하지 않는 것

| 하지 않는 것 | 이유 또는 맡은 곳 |
|---|---|
| 제보 보상(포인트·리워드) | 감사 문화로 갈음한다. 라맵 규모에선 보상 운영 부담이 크고, 조건부 외적 보상은 내재 동기를 훼손한다 → [records 금지](../records/prd.md) |
| 유형을 고르는 별도 페이지·탭(`/report` 유형 3탭) | 진입이 뚝 끊기고 수정 제보에 매장을 특정할 수 없었다. `/report`는 리다이렉트로만 남긴다 |
| 등록 폼의 장르 칩·접힘 상세층(영업시간·메뉴 등)·입력 예시 플레이스홀더 | 등록 폼은 링크 우선이다(P-05) |
| 홈 지도 화면 중심을 핀으로 첨부하는 토글 | 시트가 지도를 덮어 조준할 수 없고 운영자가 그 좌표를 믿을 수 없다. 대신 중앙 십자선 [핀 피커](design.md#핀-피커)를 쓴다 |
| Supabase 대시보드에서 하는 검수 | 파트너가 쓰기 어렵고 사진을 보며 판정하기 불편하다 |
| 푸시·이메일·카카오톡 통지 | 검수 결과 피드백 범위 밖 → [결정](decisions/0023-report-results-tab.md) |
| 포인트·랭킹·배지 | 검수 결과 피드백 범위 밖 → [결정](decisions/0023-report-results-tab.md) |
| 이의 제기 | 검수 결과 피드백 범위 밖 → [결정](decisions/0023-report-results-tab.md) |
| 공개 안 됨 사진의 재제출 | 검수 결과 피드백 범위 밖 → [결정](decisions/0023-report-results-tab.md) |
| 인허가 diff 확인(월 1~2회)·최종확인일 오래된 순 재확인 | data 모듈 → [data 설계](../data/design.md). 목표는 완벽 추적이 아니라 "라멘GPS·자작 지도보다 덜 낡은 상태"다 |

### 단계

| 단계 | 담는 것 |
|---|---|
| 현재 | 제보 폼, 검수, 검수 결과 피드백. 재처리하면 결과를 덮어쓴다 |
| 제보량이 늘 때 | 전체 처리 이력 테이블 |
| 3막 | 특정 제보자가 반복적으로 정확하면 신뢰 제보자 우대 |

| P-04 | 폐업·휴업 제보 | 별도 유형이 아니라 정보 수정의 항목 하나다(캐치테이블·구글·다이닝코드 관례) | 없음 |
