# 시드는 보편 추출 × 디깅 보강 2층으로 만든다

## 맥락

LOCALDATA 상호 키워드만으로는 상호에 '라멘'이 없는 전문점을 놓친다. 지도사 장소 데이터는 저장할 수 없다.

## 결정

**1층 — 보편 추출(자동, 넓게)**
- 후보 = **키워드 매칭(주력, LOCALDATA·상가정보 양쪽)** ∪ **(상가정보 업종 I20303 "일식 면 요리" ∩ 제외어 통과)(보조 발굴)**.
- 두 소스를 상호 정규화 부분 매칭 + 위치 호환(좌표 500m 또는 주소 구 일치)으로 조인한다. LOCALDATA는 폐업·인허가 상태, 상가정보는 좌표·발굴을 맡는다. 한쪽에만 있는 행도 후보로 남긴다(출처 표시).
- 좌표는 상가정보 WGS84 기본, LOCALDATA(EPSG:5174 변환) 좌표와 150m 넘게 어긋나면 플래그.

**2층 — 디깅 보강(수동, 깊게)**
- 디깅 소스(미디어 목록, 라멘 갤러리 정리글, 매장 공식 인스타)에서 가게의 **존재를 인지**한다. 후보 풀에 있으면 근거·태깅 초안을 넣고, 없으면 신규 후보로 추가한다(사실 정보는 공공데이터·공식 채널에서 확인). 저작권 경계는 [0018](0018-digging-source-copyright.md).
- 디깅 이름을 인허가·상가정보 전체에서 정규화 완전 일치로 다시 찾아 후보에 넣는다(2자 상호 명점 발굴).

**(선택) 카카오 아웃링크 매칭**
- 카카오 장소 ID·place_url은 운영자가 **수동으로** 넣는다. 검색 API로 자동 배치 매칭은 하지 않는다(응답의 다른 필드가 스치는 구조 자체를 피한다).

## 근거

- 서울 실측: I20303 603건 중 키워드 매칭 라멘집의 20%(48건)가 I20303 밖으로 오분류 → 주력 축 불가. 키워드 미포함 I20303 413건에 제외어를 적용하면 34건으로 줄고 그 안에 키워드가 못 잡는 체인(아오리의행방불명·산쪼메·멘무샤·히노아지·멘부리·진가와)이 있다 → 보조 발굴로 유효.
- 인허가(279) > 상가(238), 상호 완전일치 조인 72% — 어느 쪽도 단독 완전하지 않다.
- 이름만으로 조인하면 체인 다지점이 1행으로 붕괴 → 위치 호환 조건 필요. 부분 매칭 하한은 한글 2자 상호(쇼부·킨카) 때문에 2자.
- 네이버 지역정보는 어떤 필드도 저장 불가(오픈API 약관 7.3③ "지역정보 DB화" 금지 명시). 카카오 로컬은 장소 ID·place_url만 저장 허용(데브톡 151335 "공공데이터 자체 DB에 ID·URL만 배치 매칭" 승인, 151265·151271·150642 좌표 불허, 150668 상호명 불허) → [공통 결정](../../../decisions/0002-third-party-data-boundary.md)
- 상세 실측·출처 → [조사](../research/2026-09-02-seed-source-deep-research.md)

## 버린 안

- 파트너 수동 큐레이션(초기 안 — 서울 핵심 상권 50~100곳을 LOCALDATA 키워드 추출 + 파트너 온라인 조사로 채우고 나머지는 커뮤니티 기여에 맡김): 상호에 '라멘'이 없는 전문점을 놓치고 전국 시드로 넓힐 수 없다.
- I20303 전량 합집합: 우동·소바 413건 검수 부담.
- OSM: 서울 라멘 POI 37건 + ODbL share-alike 오염 리스크.
- 네이버 지역정보 발굴: 약관상 저장 불가.
- 카카오 로컬 API 자동 배치 매칭: 저장 불허 필드가 스친다.
