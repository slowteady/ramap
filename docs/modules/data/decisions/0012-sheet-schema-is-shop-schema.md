# 시트 스키마가 곧 매장 데이터 스키마다

## 맥락

매장 데이터를 DB·어드민 없이 시작해야 했다. 태깅 작업 형식과 앱 데이터 형식이 따로 놀면 마이그레이션이 생긴다.

## 결정

- 시트(TSV) 헤더 = 매장 데이터 스키마. 컬럼을 확정하면 시트 → `data/shops.json` → 앱으로 마이그레이션 없이 이어진다.
- 시트 헤더는 코드(`SHEET_HEADER`)와 1:1. 컬럼 추가·변경은 반드시 문서([data 설계](../design.md))와 함께 고친다.
- 동기화는 행 단위로 검증 문제를 모두 모아 보고하고, 문제가 하나라도 있으면 `shops.json`을 바꾸지 않는다.
- 폐업은 행 삭제가 아니라 **상태 변경**이다(기록 보존).
- 분류 칸은 자유 텍스트를 받지 않는다(택소노미 라벨만 — 오타는 나중에 전부 재작업이 된다).
- Google Sheets API에 직결하지 않고 TSV 파일을 입력으로 쓴다(자격증명 불필요).

## 근거

- DB 스키마·어드민을 따로 만들 필요가 없다. 이력은 Git이 가진다.
- 첫 에러에서 멈추면 대량 태깅 결과를 한 번에 고칠 수 없다.
