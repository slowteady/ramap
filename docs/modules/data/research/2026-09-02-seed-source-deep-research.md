# 시드 소스 딥리서치와 실측

원문: `docs/plans/2026-09-02-seed-pipeline-v2.md`의 조사·실측·드라이런 절 (원문 그대로). 설계·결정은 [data 설계](../design.md#시딩).

## 조사 결론 요약 (2026-09-02 딥리서치, 근거는 하단)

1. **네이버 지역정보는 어떤 필드든 저장 불가** — 오픈API 약관 7.3③이 "지역정보 DB화"를 금지 예시로 명시, 완화 답변·유료 경로 없음. 발굴 파이프라인에서 제외
2. **카카오 로컬 API는 장소ID·place_url만 저장 허용** — 데브톡 운영진 반복 승인. "공공데이터 자체 DB에 ID·URL만 배치 매칭" 시나리오가 명시 승인됨(스레드 151335). 좌표·주소·카테고리·상호명은 불허(상호명은 답변 상충 — 비권장). 임시 저장도 저장
3. **업종 재현율은 공공데이터로 해결** — 소진공 상가(상권)정보 업종 소분류 `I20303 "일식 면 요리"` 실존(실데이터 확인), WGS84 좌표 직제공, 라이선스 "제한 없음". 상호에 '라멘' 없는 전문점을 잡는다 (소바·우동 혼입은 제외어+검수로)
4. **좌표 보정 합법 경로** — juso.go.kr 좌표제공 API(출입구 좌표, EPSG:5179): 지도사 지오코딩 저장 금지에 저촉되지 않는 유일 확인 경로 (사업자 신청·승인 필요)
5. **판례**: 크롤링은 형사 무죄여도 민사에서 짐(여기어때 성과도용 10억, 사람인 DB권 2.5억) — 지도사·경쟁 서비스 크롤링 배제 재확인
6. **디깅 소스는 발굴 단서로 적법** — 상호·주소·존재 같은 사실은 저작권 비보호. 단 목록의 선정·배열 통째 이식(편집저작물)과 서술 복사는 금지
7. OSM 기각 (서울 라멘 POI 37건 + ODbL share-alike 오염 리스크)

## 1층 실측 (2026-09-02)

**실측 (상가정보 서울 202606 CSV, 다운로드는 data.go.kr 15083033에서 비로그인 가능 — 전국 zip 352MB):**
- 서울 I20303 = 603건, 상호 키워드 매칭(전 업종) = 238건, 교집합 190건
- **I20303은 주력 축이 될 수 없음**: 키워드 매칭 라멘집의 20%(48건)가 I20303 밖(일식 회/초밥·분식·베트남식 등 오분류 — 멘야코노하도 "일식 회/초밥"). 업종 분류 자체가 부정확
- **I20303은 보조 발굴로 유효**: 키워드 미포함 413건에 제외어(우동·소바·돈가스·초밥·카레·규동·덮밥 등) 적용 시 **34건**으로 압축되고, 그 안에 키워드가 못 잡는 라멘 체인 실재 — 아오리의행방불명·산쪼메·멘무샤·히노아지·멘부리·진가와
- 좌표: I20303 603건 전부 유효 WGS84 (불량 0)

**확정 설계**: **키워드 매칭(주력, 상가정보·LOCALDATA 양쪽에 적용) ∪ (I20303 ∩ 제외어 통과)(보조 발굴)** — I20303 전량 합집합은 기각(우동·소바 413건 검수 부담)
- **조인**: 상호 정규화+주소로 두 소스 매칭 — LOCALDATA가 폐업·인허가 상태 담당, 상가정보가 좌표·발굴 담당. 한쪽에만 있는 행도 후보 유지(출처 표시). 서울 후보 규모 ~270건(중복 제거 전) — 시트 검수 가능
- **좌표**: 상가정보 WGS84 기본 → LOCALDATA(EPSG:5174 변환, 기존 코드) 좌표와 대조 → 150m 초과 시 `coord: mismatch` 플래그 (juso 보정은 백로그)
- 산출: `data/out/candidates.tsv` — 컬럼 추가: 출처(localdata/상가/양쪽/I20303발굴), 좌표 플래그
- **조인 실측 완료 (2026-09-02, 서울시 인허가 CSV 53.7만 행)**: 인허가 키워드 매칭 571건 중 영업 중 279건(폐업·취소 292건 필터 — 인허가 조인의 핵심 가치 실증), 영업 중 좌표 누락 0. 상가정보 키워드 238건과 상호 완전일치 조인 72% — 미매칭 28%는 지점명·수식어 표기 차이("쇼부" vs "쇼부일본라멘강남고속터미널1호점")가 주원인이므로 구현 시 **정규화 부분 매칭 + 행정동 보조 키** 필요. 인허가(279) &gt; 상가(238)로 어느 쪽도 단독 완전하지 않음 — 합집합 재확인
