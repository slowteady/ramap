# 데이터 갱신 라운드 2026-10 — LOCALDATA 최신본 대조

2026-10-05. 1,330곳 게재 상태에서 한 달 만의 첫 정기 갱신. 이 문서는 절차·판단 근거·결과·검토 잔여를 담아 다음 라운드를 그대로 재현할 수 있게 한다.

## 원천과 접근

- LOCALDATA 웹(`www.localdata.go.kr`)은 2026-04-16 공식 종료(공공데이터포털로 이관). **파일 서버는 살아 있다**: 안내 허브 `https://file.localdata.go.kr/file/general_restaurants/info`(HTML) → 실제 파일 `https://file.localdata.go.kr/file/download/general_restaurants/info`
- 조건: `Referer: https://file.localdata.go.kr/file/general_restaurants/info` 헤더, 일반 UA. 302 없이 206/200, `Accept-Ranges` 지원. 전국 일반음식점 CSV **698,680,673B·2,301,949행**, EUC-KR(헤더 `charset=UTF-8`는 거짓), 일 갱신(2일 전 기준)
- 헤더 39열 중 사용: `사업장명`·`도로명주소`·`지번주소`·`영업상태명`·`폐업일자`·`관리번호`·`업태구분명`·`좌표정보(X)/(Y)`. 다른 업종은 허브 페이지의 `/file/<slug>/info` 링크에서 slug 확인(예: `bakeries`, `animal_hospitals`)

## 절차

```bash
curl -L -H "User-Agent: Mozilla/5.0" -H "Referer: https://file.localdata.go.kr/file/general_restaurants/info" \
  -o /tmp/general_restaurants.csv https://file.localdata.go.kr/file/download/general_restaurants/info
npm run refresh-localdata -- /tmp/general_restaurants.csv 2026-10   # 38초, data/out/refresh-{new,closed,unmatched,moves}.tsv
# 검토 후 candidates.tsv에 반영: 폐업 → 상태=폐업·상태변경일=폐업일자·메모 / 신규 → 행 추가(refresh-new.tsv 그대로)
# 신규 후보 조사 배치(Daum 검색 WebFetch 전용 에이전트) → data/enrichment/refresh-2026-10.json
npm run enrich-candidates -- data/out/candidates.tsv data/enrichment/*.json
npm run sync-sheet -- data/out/seed.tsv        # 소실 0 검수 후에만
npm run audit-integrity                         # 2026-10-27~ 필수: data/out/integrity-report.md의 소실·계보 변경 전부 사유 확인 (data-integrity 스킬)
npm run indexnow                                # 배포 후
```

재현성 기준선: 라운드 시작 전 `enrich-candidates → parseSheetTsv(seed.tsv)`가 현행 `shops.json`과 **1,330곳 내용 완전 동일**함을 먼저 확인했다(이게 깨져 있으면 갱신 전에 원인부터).

## 분류 로직 (`scripts/lib/refresh.ts`)

- 같은 매장 = 상호 포함관계(정규화 후 2자 이상) **그리고** 같은 건물. 상호 단독 비교 금지(체인 다지점·재인허가)
- 같은 건물 = `sameRoadAddress`(상세·괄호부 제거 후 동일) **또는** 도로명+건물번호 동일 + 시군구/읍면동 토큰 1개 이상 겹침. 세종처럼 시군구가 없으면 시도 비교로 폴백
  - 근거: **2026 행정구역 개편**으로 LOCALDATA 주소 접두부가 대거 바뀜 — 화성시 동탄구·병점구·만세구 신설, 인천 영종구·제물포구·검단구·서해구, 전남광주통합특별시. 이 보정 전엔 미발견 128·신규 40이었고, 보정 후 119·33(코이라멘 평택고덕점 류 오탐 제거)
  - 기존 데이터 결함: 세종 주소가 `세종특별자치시 세종특별자치시 …`로 시도 중복 — candidates.tsv 원천 수정 대상(후속)
- 폐업 = 기지 후보와 매칭되는 최신 행이 **모두** 폐업 상태(폐업 행과 영업 행이 공존하면 재인허가로 보고 영업 유지)
- 미발견 = 게재 매장인데 매칭 행이 0 — 자동 폐업 금지, 검토 목록만
- 신규 = 라멘 키워드 상호 + 영업 + 어떤 기지 후보와도 미매칭, 같은 이름+건물 중복은 접음
- **자동 제외**(2026-10-15 추가, `data/out/refresh-excluded.tsv`): ① 임시 영업장 — 주소·상호에 `축제|페스티벌|행사장|박람회|부스|푸드트럭|임시`(`isTemporaryVenue`) ② 제외 목록 — `data/refresh-exclusions.tsv`(추적, 상호·주소·사유)와 상호 포함관계+같은 건물. 사람이 중복 인허가·비라멘으로 판정한 행은 candidates에서 지워도 매 라운드 신규로 재등장하므로, 판정 시 이 파일에 한 줄 추가한다. 10/15 전국본 검증: 신규 6 → 3(후우미라멘 축제장·초이라멘 새문안·노조미 삼학동 제외), 이전 의심 3 → 0

## 신규 행과 기존 enrichment의 상호작용 (주의)

`enrich-candidates`의 `matchEnrichment`는 정규화 상호의 **접두 일치**(3자 이상)로 묶고, `mergeMatched`는 **장르(soups·forms·lineages)는 동명 전체에서 병합**, 위치·영업시간·실존/업종 판정은 exact 상호+`addrHint`가 맞는 항목에서만 가져온다. 따라서 신규 행은 조사 전이라도 동명 체인의 enrichment가 있으면 게재 게이트를 통과한다(2026-10 라운드: 33건 중 18건이 조사 전 게재 — 노조미라멘·환장라멘·멘야고코로처럼 디깅 때 조사됐으나 인허가 행이 없던 매장은 정당, `라멘야 삼미당`←"라멘야"처럼 범용 접두어 승계는 오염 가능). 라운드마다 신규 행의 자동 게재분을 반드시 눈으로 검토하고, 오염 건은 exact 상호+addrHint 항목으로 덮어쓴다.

> **2026-10-27 갱신:** 위 승계는 이제 같은 체인으로 판정될 때만 일어난다(`isSameChain` — 지점 표기·단어 경계·주소 지명). 계보는 `chainWide: true` 항목만 지점에 넘어가고, `addrHint` 항목의 인스타는 그 주소 매장에만 붙는다. 신규 행이 기존 상호와 접두로 겹치면 같은 체인인지 다른 가게인지 근거에 명시하고, 재생성 후 `npm run audit-integrity` 리포트로 검수한다. 기준·절차는 `.claude/skills/data-integrity/SKILL.md`.
