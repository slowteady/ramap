# 경쟁·레퍼런스 프로덕트 기능 벤치마크

2026-09-05 조사(앱스토어·플레이스토어·인스타·커뮤니티 실측) 기준. 확인된 사실만 기록 — 앱 내부 미확인 항목은 표기. 레퍼런스 채택 판단의 원천.

## 1. 라멥 (舊 라맵) — 직접 경쟁, 한국 네이티브 앱

1인 개발(안드 개발자 "페토"), iOS 정식 출시 2026-08-12, 다운로드 100+·인스타 334팔로워 수준. 웹 없음. 매장 ~760곳(개발자 언급).

| 기능 | 내용 | 라맵 현황 | 판단 |
|---|---|---|---|
| **라멘 이벤트 피드** | 한정 메뉴·팝업·콜라보 소식 모음 + 알림 | 없음 | **따올 가치 1순위** — 라오타층의 실수요(한정메뉴 정보가 디시 라겔의 주 트래픽)이고 우리 신규 오픈 데이터 파이프라인과 결이 같다. 수집 경로(제보·인스타 모니터링) 설계 필요 |
| 휴무·영업시간 변경 공지 | 매장 임시휴무를 피드로 알림 | 정적 데이터만 | 이벤트 피드와 같은 축 — 제보 기반으로 묶어 검토 |
| 좋아요 기반 지역·메뉴별 랭킹 | 유저 좋아요 집계 랭킹 | 없음 (완식 집계가 잠재 원료) | 보류 — 유저 수 적을 때 랭킹은 왜곡·빈약. 완식 집계 축적 후 |
| 라멘 종류 필터·검색 | 메뉴 종류 수준 분류(체계적 3축 아님 — 내부 미확인) | **우리가 우위** (soup·form·lineage 3축) | — |
| 매장 숨김 | 목록에서 특정 매장 숨기기 | hideVisited(완식 숨김)만 | 참고 — 완식 숨김이 상위 호환에 가까움 |
| 제보 | 신규·오류수정·인스타 링크/사진 | 있음 (핀 피커까지) | 동등 이상 |
| 카카오 로그인 | | 있음 | 동등 |

## 2. 家系マニア (일본 iOS) — PO 지인 추천 공식 벤치마크

이에케(家系) 장르 전문. 2024-06 출시, 평점 4.8(27건). 舊명 家系ラーメンマニア. App Store id6767432534.

| 기능 | 내용 | 판단 |
|---|---|---|
| **계보(系譜) 시각화** | 直系·壱系·六角系 계보를 색분류 지도 + 그래프/도표로 | **따올 가치 최상** — 우리 lineage 데이터(이에케·지로계)와 동일 문제의 유일한 실구현 선례. `/style/iekei` 페이지에 계보도를 얹으면 장르 쿼리 SEO 콘텐츠와 시너지 (P3와 연결) |
| **구조화 기록 필드** | 리뷰를 자유 텍스트 대신 면 굳기·국물 농도·기름량·토핑·스코어 필드로 수집 | **따올 가치 상** — 완식 기록 확장 방향. 자유 리뷰와 달리 집계·필터 가능한 데이터 자산이 됨. 이에케 주문 관습(硬め·濃いめ·多め)이 원형이므로 한국 문맥 필드 재설계 필요 |
| 방문 배지 (10/50/100잔) | 방문 수 마일스톤 배지 | 따올 가치 중 — 완식 카운트에 수집 동기 부여. 구현 가벼움 |
| 착돈 타임라인 SNS | 방문 기록 공유 피드 | 보류 — SNS는 유저 밀도 필요, v1 범위 밖 |
| 매장 상세에 계보·제면소 | 제면소(면 공급처) 정보 축 | 참고 — 자가제면 태그는 있음, 제면소 DB화는 데이터 수집 비용 대비 검토 |

## 3. ラーメンデータベース (ramendb.supleks.jp) — 일본 최대, 웹 중심

2005년~, 47개 도도부현 수만 매장, 유저 독자 스코어+장단점 리뷰. "타베로그화하지 않은 운영"으로 유명(JBpress).

- **유저 스코어 기반 랭킹의 신뢰 구축** — 별점 인플레 없는 독자 스코어 체계. 우리 랭킹 도입 시 원형
- **지역 서브도메인 분할**(도쿄·군마 등) — 우리는 /area 경로로 동일 문제 해결 중, 참고만
- **장르 확장 가능한 플랫폼 구조**(카레·차항·교자 DB로 확장) — 먼 미래 참고
- 웹 중심이라 **SEO 관점의 실질 레퍼런스** — 앱(안드 평점 2.8)은 부실해도 웹으로 생존하는 모델

1. **계보 시각화** (家系マニア) — lineage 데이터 이미 보유, P3 장르 콘텐츠와 시너지, 경쟁 전무

3. **구조화 완식 기록** (家系マニア) — 완식 신뢰도 논의(현장 인증 플래그)와 함께 설계
