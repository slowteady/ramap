# 검색 (2026-09-01)

매장명·장르·동네로 매장을 찾아 지도로 보내는 검색. 전 데이터가 클라이언트에 있으므로(SSG pins, 수십~수백 규모) 서버·API 없이 즉시 필터링한다.

## 실측 근거 (2026-09-01, 카카오맵·캐치테이블·네이버지도·오늘의집 모바일 웹 — 스크린샷 26장: 세션 스크래치패드 `search-refs/`)

1. 진입점은 4곳 모두 **상단 고정 풀폭 검색바**(캐치테이블은 로고+input+아이콘 한 행). 아이콘 진입은 커머스뿐 — 지도 서비스엔 바가 표준
2. 입력 화면 = **카테고리 바로가기 + 최근 검색 두 섹션**. 인기 검색어를 쓰는 곳은 0/4 — 생략 확정
3. 자동완성은 **1글자부터**, 제안 유형 구분은 캐치테이블이 벤치마크(카테고리: 아이콘+매장 수 "라멘 189" / 매장: 상호+주소). 하이라이트는 완성부 볼드(캐치·오늘의집) 채택
4. 결과: 대형 지도사는 리스트 전환, 캐치는 지도+시트 유지 + 검색어→카테고리 필터 자동 매핑 — 라맵은 이미 지도+시트라 캐치 패턴 직접 참고
5. **빈 결과 = "검색결과가 없어요" + 신규 장소 등록 유도 버튼**(카카오·네이버 공통, 네이버는 결과 있어도 상시 노출) — 제보 재설계 미결("검색 결과 없음 → 등록 진입") 해소

## 설계

### 진입점 — 홈 헤더 개조 (캐치테이블 문법)

```
[라맵]  [ 🔍 라멘집·장르·동네 검색 ]  [프로필]
```

- 헤더의 빈 공간을 검색바(읽기 전용, 탭 전용)로. 탭 → 검색 오버레이
- 필터 칩 행·제보 버튼은 그대로

### 검색 오버레이 (풀스크린, `?search=1`)

- 제보 시트와 같은 URL 쿼리 패턴 — **뒤로가기 = 닫기**, 아래→위 전환
- 구성 (위→아래):
  1. `[←] [input (자동 포커스, X 클리어)] ` — 검색어는 여기 유지
  2. **입력 전**: 장르 바로가기 칩(국물 8종, 매장 수 0인 값 제외) + 최근 검색(localStorage 최대 10, 개별 ×·전체 삭제, 시계 아이콘)
  3. **입력 중 (1글자부터, 디바운스 없음)**: 제안 리스트 2종 혼합
     - **장르**: `[아이콘] 니보시 · 4곳` — 탭 → 해당 필터 적용 + 오버레이 닫기 (캐치의 키워드→필터 매핑)
     - **매장**: `상호 — 동네` — 탭 → `?shop=` 선택 + 지도 이동 + 닫기
     - 하이라이트: 매칭부 외 완성부 볼드
  4. **빈 결과**: "검색 결과가 없어요" + "찾는 라멘집이 라맵에 없다면 알려주세요" + [라멘집 등록하기] → `?report=new`

### 매칭 규칙 (순수 함수)

- 대상: 매장명(지점명 포함), areaLabel, 장르 라벨(국물·종류·스타일 taste)
- 부분문자열 매칭(네이버식 중간 매칭) + **초성 매칭**("ㄴㅂㅅ" → 니보시) — 초성 추출은 자체 순수 함수(라이브러리 미도입), 공백·대소문자 무시
- 정렬: 접두 일치 > 부분 일치, 장르 제안 먼저(최대 3) → 매장(최대 10)
- 최근 검색 저장: 매장/장르 선택 시에만 저장(무의미한 미완성 입력 미저장)

### 상태·URL

- 오버레이 열림: `?search=1` (push, 닫기 back) — 검색어 자체는 URL 미반영(선택 즉시 닫히는 내비게이터라 공유 가치 없음, 상태 URL화 원칙의 기록된 예외)
- 결과 화면 없음 — 선택이 곧 지도 이동/필터 적용

## 미결

- 동네 단위 제안("성수" → 지역 이동) — areaLabel 매칭은 매장 제안으로 커버, 지역 자체 이동은 데이터가 늘어 지역 단위 탐색 수요가 실증되면
- 검색어 URL 공유(`?q=`) — 결과 리스트 화면이 생기는 규모가 되면 재검토
