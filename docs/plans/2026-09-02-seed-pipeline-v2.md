# 시드 파이프라인 v2 — 보편 추출 × 디깅 보강 2층 구조

2026-09-02 확정 (딥리서치 3갈래 후 PO 결정: "보편적으로 뽑고, 디깅 글로 보강"). 이 문서만 읽고 다른 에이전트가 구현을 이어받을 수 있어야 한다.

## 조사 결론 요약 (2026-09-02 딥리서치, 근거는 하단)

1. **네이버 지역정보는 어떤 필드든 저장 불가** — 오픈API 약관 7.3③이 "지역정보 DB화"를 금지 예시로 명시, 완화 답변·유료 경로 없음. 발굴 파이프라인에서 제외
2. **카카오 로컬 API는 장소ID·place_url만 저장 허용** — 데브톡 운영진 반복 승인. "공공데이터 자체 DB에 ID·URL만 배치 매칭" 시나리오가 명시 승인됨(스레드 151335). 좌표·주소·카테고리·상호명은 불허(상호명은 답변 상충 — 비권장). 임시 저장도 저장
3. **업종 재현율은 공공데이터로 해결** — 소진공 상가(상권)정보 업종 소분류 `I20303 "일식 면 요리"` 실존(실데이터 확인), WGS84 좌표 직제공, 라이선스 "제한 없음". 상호에 '라멘' 없는 전문점을 잡는다 (소바·우동 혼입은 제외어+검수로)
4. **좌표 보정 합법 경로** — juso.go.kr 좌표제공 API(출입구 좌표, EPSG:5179): 지도사 지오코딩 저장 금지에 저촉되지 않는 유일 확인 경로 (사업자 신청·승인 필요)
5. **판례**: 크롤링은 형사 무죄여도 민사에서 짐(여기어때 성과도용 10억, 사람인 DB권 2.5억) — 지도사·경쟁 서비스 크롤링 배제 재확인
6. **디깅 소스는 발굴 단서로 적법** — 상호·주소·존재 같은 사실은 저작권 비보호. 단 목록의 선정·배열 통째 이식(편집저작물)과 서술 복사는 금지
7. OSM 기각 (서울 라멘 POI 37건 + ODbL share-alike 오염 리스크)

## 설계 — 2층 구조

### 1층: 보편 추출 (자동, 넓게)

- **소스 합집합**: LOCALDATA 일반음식점(현행: 상호 키워드 필터) ∪ 소진공 상가정보 분기 CSV의 `I20303 일식 면 요리` 전체
- **조인**: 상호 정규화+주소로 두 소스 매칭 — LOCALDATA가 폐업·인허가 상태 담당, 상가정보가 업종 시그널 담당. 어느 한쪽에만 있는 행도 후보로 유지(출처 표시)
- **좌표**: 상가정보 WGS84 기본 → LOCALDATA(EPSG:5174 변환, 기존 코드) 좌표와 대조 → 거리 임계값(예: 150m) 초과 시 후보 행에 `coord: mismatch` 플래그 (juso 보정은 후속 — API 승인 절차 필요해 v2 스코프 밖, 우선 수동 핀)
- **소바·우동 혼입 필터**: 제외 키워드(소바·우동·돈가스 등) 1차 제거 + 나머지는 시트에서 검수
- 산출: 현행과 동일한 `data/out/candidates.tsv` (시트 붙여넣기용) — 컬럼 추가: 출처(localdata/상가정보/양쪽), 좌표 플래그

### 2층: 디깅 보강 (수동, 깊게 — "덮어쓰기"의 정확한 의미)

- **디깅 소스**: Hypebeast 서울 라멘 67선, 디시 일본 라멘 마이너 갤러리·라멘 미니 갤러리 정리글("가본 곳 정리"·"오픈 리스트"), 매장 공식 인스타
- **동작**: 디깅 글에서 가게의 **존재를 인지** → 1층 후보 풀에 있으면 verification 근거·태깅 초안(장르·계보)을 시트에 입력, 없으면 신규 후보로 추가(사실 정보는 LOCALDATA·공식 채널에서 확인해 기입)
- **저작권 경계 (준수 필수)**: 글의 서술·평가 문장 복사 금지 / 특정 목록의 선정·배열 통째 이식 금지 / 태깅은 글을 참고한 운영자의 자체 판단으로 기입. 시트에 참고 링크 컬럼(내부 근거용, 미게재)
- 이 층은 18.데이터전략 v1 "파트너 온라인 조사 태깅"의 공식화·확장 — 새 프로세스가 아니라 발굴 단서 소스를 명시한 것

### (선택) 카카오 아웃링크 매칭

- 시드 확정 후 매장별 카카오 장소ID·place_url을 **운영자 수동 배치**로 시트에 입력 (저장 허용 필드만 — 승인된 경계). 상세 페이지 "카카오맵에서 보기" 아웃바운드 링크로 활용. 자동 API 배치 매칭은 하지 않는다(검색 API 응답의 다른 필드가 스치는 구조 자체를 회피)
